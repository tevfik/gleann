# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Added
- **`gleann index watch --quiet`.** Silences the status lines (start, initial sync, per-change updates, stop) and the embedded `llama-server` start, as `index build --quiet` and `index sync --quiet` do; errors and warnings stay on stderr. `--help` and `docs/configuration.md` list it.
- Metadata filter indexes: the first eq/in/exists filter search on a meta key creates a SQLite expression index for it (on demand, up to 16 keys per index database, indexes up to 200K passages; `EnsureFilterIndexes` for larger ones), so filtered searches no longer scan the whole passages table. Values SQLite and Go decode differently (numbers beyond float64, duplicate keys, non-UTF-8 bytes, a raw NUL byte after valid JSON) are verified by the filter engine. No migration; older binaries keep the indexes exact on write and never read them. See docs/plans/010-filter-index.md.

### Fixed
- **A failed memory refresh is shown in the classic chat too, and once per failure run in both chats.** `gleann chat --classic` called the silent `memory.InjectRepoContext`; it now uses `InjectRepoContextErr` and adds a system line ("Memory not injected: ...") through the stream-start message, and the answer still runs. Both the classic chat and the agent chat (failed "memory" card) report the first failure only, and report again after a success is followed by a new failure, so a store that stays broken is no longer announced on every turn. The notice is also shown again after `/new`, `/clear` or loading a conversation (the visible messages were cleared), and classic-chat answer tokens are no longer dropped when a system line lands after the streaming placeholder.
- **Opening the embedding cache no longer lists the whole cache directory.** `NewCachedComputer` ran a glob over every file in the cache to remove temp files left by killed processes, on every CLI build, sync, search and server searcher load (about 580 ms at 200K entries, 1.4 s at 515K). The sweep now runs at most once an hour per directory (a `.stale-sweep` stamp file in the cache directory, shared by all processes) and reads names without a glob; opening a 200K-entry cache went from 580 ms to under 1 ms once swept (27 ms averaged over 5 opens including the one sweep, itself 135 ms instead of 580 ms). Stale temp files (older than an hour) are still removed, in-flight writes are not.
- **Test home guards also clear the `GLEANN_*_DIR` overrides.** The private-`HOME` `TestMain`s of `internal/indexing`, `internal/multimodal` and `internal/vault` now unset every `GLEANN_*_DIR`/`_DIRS` variable, and a guard test fails if one points outside the private home. CI has a new Linux job (`scripts/check-test-home.sh`) that runs the suite with `HOME` at an empty directory and fails if a file appears in it.
- **Windows: `PATCH /api/indexes/{name}` no longer answers 500 under concurrent updates.** The handler now does its read-modify-write in one locked `UpdateIndexMetaResult` (no pre-read and no re-read outside the per-index lock), index metadata reads retry the transient Windows sharing errors (`internal/fsretry.ReadFile`), and a not-exist error from the metadata write is a 500 (`ErrIndexMetaWrite`), not a 404.
- **Windows: replacing a file that is being read no longer fails.** `PATCH /api/indexes/{name}` (and any index metadata update), config, token, conversation and embedding-cache writes replace their file with `os.Rename`, which Windows refuses ("Access is denied" / sharing violation) while a reader still has the target open; they now go through `internal/fsretry`, a bounded retry (about 1 s, short backoff, Windows error codes only; a plain rename elsewhere). This was the cause of the Windows CI failure of `TestPatchIndexConcurrent` (2 of 100 PATCHes answered 500).
- **`internal/indexing` tests no longer use the real embedding cache.** The suite built indexes against `$HOME/.gleann/cache/embeddings` with a new model name per run, so the directory grew without bound and every build scanned it for stale temp files (about 2 s per build at 500K entries under `-race`); the package now runs with a private `HOME`. `go test -race ./internal/indexing/` went from 1166 s to 235 s on the same cores.
- **Tests of `internal/multimodal` and `internal/vault` no longer touch the real home directory.** They created `~/.gleann/cache/multimodal` entries and `~/.gleann/vault`; both packages now run with a private `HOME` like `internal/indexing`. A run of every test package with `HOME` pointed at an empty directory now leaves it empty (before: 1441 files from `internal/indexing`, 2 from `internal/multimodal`, 2 empty directories from `internal/vault`).
- **`gleann ask` honours `--`, and `ask` and `search` read no flag after it.** Everything after `--` is question text, verbatim: `ask idx -- --graph why` asks "--graph why" instead of dropping both `--` and `--graph`, and `search idx -- why --index-dir /x` no longer changes the index directory (the shared config flags `--model`, `--top-k`, `--index-dir`, ... stopped at `--` nowhere before).
- **`--help` as the value of a value-taking flag is not a help request** in `ask`, `chat`, `setup`, `service` and `graph <subcommand>` (`ask --model -h`); the documented rule that `--help` after `--` is text is unchanged.
- **`gleann graph hook --help` prints the hook usage** instead of the general graph usage, and names the `GLEANN_GRAPH_INDEX` variable the hook needs. The installed post-commit hook now checks that variable first and stays silent when it is unset and never ends the hook early, so lines after it in `post-commit` still run (it used to print "rebuilding graph index..." and then do nothing); reinstall the hook to get the new script.
- **`gleann ask --help` no longer presents `--classic` as a working flag.** It is a `gleann chat` flag; `ask` only tolerates it, and the usage now says so.
- Pre-selection of `source`/`file` filters resolves the meta `source` key of passages stored without a source column.
- Exact scoring of few filter matches is no longer refused above 200K passages when a filter index can answer the pre-selection.
- Filter pre-selection by the table pass no longer decides from meta text that SQLite reads and Go rejects (JSON5 forms, a BOM, a trailing form feed, a `"v\u0000"` key, a raw NUL byte): such rows go to the filter engine, so `exists:false` and the `file` fallback to the source column match what the engine returns. Costs about 0.55 ms per 1,000 passages of a table pass (100K passages: +55-70 ms on 250-330 ms). Field names with U+FFFD or invalid UTF-8 are left to the engine.
- Filter pre-selection by table pass no longer disagrees with the filter engine on duplicate JSON keys and non-UTF-8 bytes in meta text; a meta text of `null` no longer panics.
- **`PATCH /api/indexes/{name}` answers `404` for an unknown index** instead of `500` (detected with `errors.Is(err, fs.ErrNotExist)`); the OpenAPI response set and `docs/api.md` follow.
- **`PATCH /api/indexes/{name}` enforces index access restrictions (security).** It now applies the same `X-Gleann-Target` / `GLEANN_TAGS` check as `GET`, before the existence check, so a client restricted by `X-Gleann-Target` can neither modify nor probe other indexes. Under `GLEANN_TAGS` it behaves exactly like `GET`: an index with another tag answers `403` and a missing one `404`. A plain file named like the index answers `404`, as `GET` does.
- **Concurrent index metadata updates no longer fail or lose data.** `UpdateIndexMeta` serialises updates of one index and writes through a unique temporary file (previously parallel `PATCH`es shared one `.tmp` file and produced spurious `404`/`500` and lost updates).
- **Agent chat TUI:** the context-window limit is read under the chat lock (data race with the background probe); the probe is cancelled and awaited when the chat exits; a failure to build the repository memory context is shown as a failed `memory` card instead of being dropped silently (the answer still runs). New `memory.InjectRepoContextErr` reports the failure.
- **`--help` as the value of a value-taking flag is not a help request in the remaining commands either:** `search`, `def`, `serve`, `agents`, `install`, `multimodal analyze`, `index build|rebuild|sync|watch|remove|tag|set|info|list|repair|migrate|storage` (`search idx --kind -h` now searches instead of printing the usage); each reads its own flag table, the one it already uses to reject unknown flags. `gleann benchmark --help` now prints the usage (it had no help check).
- **`gleann serve` could return with the vault database still open.** The start-up task that prunes old upload records from `~/.gleann/vault/vault.db` was not tracked by the server's shutdown, so a server stopped right after start (or a start that failed) returned while the task still held the file; `Stop` now waits for it (bounded by its context). Visible as a failed removal of the home directory on Windows.
- **`Server.Stop` raced with `Server.Start`.** `gleann serve` stops the server from its signal handler while `Start` is still running, and both touched the HTTP server field without synchronisation (reported by the race detector). Set-up and shutdown are now ordered by a mutex; a stop during set-up makes `Start` return `http.ErrServerClosed`.

## [v1.20.2] — 2026-11-23

See [docs/releases/v1.20.2.md](docs/releases/v1.20.2.md).

### Added
- **Failure memory is scoped to a repository.** A recorded failure ("this command failed with this error") now belongs to a scope, by default the repository it was recorded in, so one project's failures no longer show up in another's context. `POST /api/blocks/failures` records one (admin token) and `GET /api/blocks/failures` lists them (query token; filters by command, paths and symbols); `GET /api/blocks/context` accepts `command`, `paths` and `symbols`; MCP `memory_failure_add` / `memory_failure_list` take an optional `scope` (`all` or `*` lists every scope); the CLI has `memory failure add|list --scope` and `memory context --symbol --scope`. Path matching is repository-relative, with a basename fallback only inside the same repository; symbols are matched by fully qualified name or suffix.
- **Full OpenAPI 3.0 route parity.** Every REST route the server registers now appears in the spec at `GET /api/openapi.json`, with `bearerAuth` declared once at the top level and each of the four public routes (`GET /health`, `GET /.well-known/agent-card.json`, `GET /api/docs`, `GET /api/openapi.json`) overriding it with an empty `security` list, so Swagger UI and Postman import see the whole API; `TestOpenAPIMatchesRegisteredRoutes` fails the build when the router and the spec drift apart.
- **`TestCallers` across MCP `gleann_impact`, REST graph `impact`, and CLI `gleann graph explain`.** Separates calling test functions cleanly into `TestCallers` / non-nil `test_callers` JSON arrays (including refreshed `sqlite_lite` REST impact goldens) alongside production `Callers`, and renders a capped, column-aligned `Test Callers` section in `gleann graph explain`.
- **MCP server instructions, tool annotations, and `MCP-06` contract suite (`5.2a`).** Adds profile-aware `WithInstructions` guidance covering every enabled tool (including custom `--tools` subsets and `gleann` vs `grep` routing), explicit read-only / destructive / idempotent / open-world annotations across all 37 tools (`15` open-world across the 8 embedder/LLM tools and 7 REST-forwarding memory/session tools vs `22` local-only tools), core-profile tool count alignment (`11` tools in `gleann mcp --help` and `docs/mcp.md`), and loopback contract tests verifying both `/api/embed` and remote `/api/blocks*` REST egress alongside local-only controls.
- **REST passage and section listings (`GET /api/indexes/{name}/passages`, `GET /api/indexes/{name}/sections`, RFC 004 G8).** Serves bounded read-only pages straight from SQLite (`ORDER BY id LIMIT/OFFSET`, default `100`, max `1000`) without loading vectors or the embedder, groups sections from passage metadata (`section_id`, `section_title`, `section_path`, `section_summary`, falling back to `heading`/`title`), enforces query token scope plus `X-Gleann-Target`/`GLEANN_TAGS` access isolation, returns `404` for missing indexes without creating `.db` files and `409` with the migration hint for format-1 indexes, and updates `docs/api.md` and the OpenAPI spec.
- **RFC 009 (draft): memory tier lifetime.** Specifies three-source TTL precedence (per-fact explicit expiry, user setting, fixed default) for short/medium memory, `EndSession` promotion rules, long-tier permanence, and `compact --dry-run`.
- **Benchmark paired comparisons and honest Ripgrep baseline.** `gleann benchmark --compare <A>,<B>` (in-run or standalone `<fileA>[:<Strategy>],<fileB>[:<Strategy>]`) computes paired bootstrap confidence intervals and exact sign tests across strategies with explicit per-metric presence tracking so omitted JSONL fields never zero-fill, documents and logs the `bench/tasks/gleann.json` fallback, validates `--per-task` creation and write errors, and removes process-global `GLEANN_BENCH_PERTASK` env mutation.
- **CI installer script test execution, `verify-go-install` tag job, and workflow permission hardening.** `.github/workflows/ci.yml` runs `scripts/test-install.sh`, `.github/workflows/release.yml` adds a post-publish `verify-go-install` job with GitHub tag pre-check, module proxy `.info` warm-up, `GOPRIVATE` direct fallback, and `$GITHUB_PATH` for `task` without `sudo`, and workflows apply least-privilege `permissions`.
- **`bench/vectordb` on real embeddings.** `cmd/exportvecs` writes the stored vectors of a gleann HNSW index to a `.fvecs` file, and `vectorbench -vectors <file>` / `filtbench -vectors <file>` run on them (queries are held out of the file). `cmd/buildbench` times a build through `gleann.NewBuilder` for `-backend hnsw` or `diskann`; `filtbench -backend diskann` measures the real search path of either backend. `bench/vectordb/gleannsearch` is the shared build-and-query helper.
- **`scripts/build-faiss.sh`** builds FAISS (static, with the C API) into `deps/faiss_install` for `make full`.
- **Feature status table in the README:** what is covered by the CI gates (core) and what is experimental (A2A, multimodal, web UI).
- **RFC 007 (accepted): multi-turn A2A tasks.**
- **RFC 008 (accepted): one retrieval service (`internal/retrieval`).**

### Security
- **The exact Go load of the code graph could reach the network.** gleann runs `go list` with `GOPROXY=off`, but with `go.sum` entries present a module path matched by `GOPRIVATE` or `GONOPROXY` took the direct route (a fetch attempt was observed). The load now also sets `GOPRIVATE=`, `GONOPROXY=none` and `GONOSUMDB=*`. The user's `GOFLAGS` are kept except `-mod`, and a vendored module loads with `-mod=vendor` instead of failing.
- **A2A: a query token could write memory and have local files read.** Through `POST /a2a/v1/message:send`, a token of scope `query` could store memory blocks (which are later injected into agents' prompts) and have the `multimodal-analyze` skill read a file of the server by path. Both now need an admin token; a query token can still search and recall memory and analyze files it attaches. With authentication off (loopback only) nothing changes.
- **`scripts/install.sh` verifies the download.** The archive is checked against the release's `SHA256SUMS`; a missing sums file, a missing entry or a mismatch stops the installation (`GLEANN_SKIP_CHECKSUM=1` skips the check).

### Fixed
- **Memory scopes written as `repo-a/` or `/repo-a` were invisible to readers.** Every write path (`POST /api/blocks`, MCP `memory_remember`, markdown import, the bbolt to SQLite migration, and the new `gleann memory remember --scope`) now stores the canonical scope, and a one-time migration on first open (`migration:scope_normalize_v3`, one transaction) rewrites the scope of rows older releases stored padded or as a literal `all`; block IDs are kept. `all` or `*`, in any case, in the query string or the `X-Gleann-Target` header, selects every scope on every block route and is never stored as a scope. Failure IDs are length-prefixed for every scope, so no two (command, error, scope) combinations share an ID; an existing row with an old-style ID is found and updated, not duplicated.
- **A query-scoped API token got 403 on `POST /api/graph/{name}/query`.** That route only reads the code graph (callers, callees, symbols in a file, impact, table of contents), so a `query` token is now enough; `POST /api/graph/{name}/index`, which writes, still needs an admin token.
- **`gleann index build --quiet` still printed status lines and the progress bar.** `--quiet` now silences them on `index build`, `index rebuild`, the dual-model build and `graph build`, as it already did on `index sync`: stdout stays empty on success, errors and warnings still reach stderr, and an explicit `--progress <surface>` still reports progress. `--dry-run` estimates and the decision-gate JSON are data and are kept. Without `--quiet` the output is unchanged (compared byte for byte against the previous build for eight commands).
- **Rollback-protected incremental sync, publication crash recovery, and vector readability checks (`S6-row6`).** Classifies missing or damaged store and `.index` faults cleanly to trigger rollback-protected rebuilds without destroying intact indexes on empty-corpus failures or transient embedder outages, guards `updateIncremental` against non-regular or unreadable `.index` files, reports unreadable/directory `.index` files in `CheckIndexHealth`, `gleann doctor`, and `gleann index repair`, preserves `has_graph` metadata across up-to-date syncs, and aligns `docs/cookbook.md`, `docs/graph.md`, and `docs/troubleshooting.md`.
- **Plugin registry versions and sound icon alignment.** Removed stale hardcoded `"version": "1.0.0"` fields for `gleann-plugin-docs` and `gleann-plugin-sound` from `plugins-registry.json` (installed/latest plugin versions are resolved dynamically from release tags), aligned the sound plugin icon in the registry (`🎙️`) with `defaultCatalog`, and added `TestCatalogRegistryParity` to verify full field parity and reject placeholder versions.
- **Exact Go call resolution now covers `_test.go` files in builds and syncs.** `LoadExact` and `LoadExactDirs` type-check each package's test files (`Tests: true`), resolving calls from internal and external tests (`go/types` `CALLS` and `IMPLEMENTS` edges, recovering `2,226+` caller edges on `gleann` itself with test-only recall `0.745` -> `0.998`), keeping and retrying broken test files cleanly during incremental sync without disturbing production edges or test-only directories, and excluding synthetic test runners without dropping standalone `*.test` `main` packages or modules.
- **CLI `--quiet` suppression across commands and provider build-tag caveats.** `--quiet` now silences the multi-index `--explain` note, `index sync` status stdout and default progress, and the embedded `llama-server` startup and shutdown messages (`search`, `ask`, `chat`, `serve`, `index build`, `index sync`, `index watch`) while keeping real errors on `stderr`; `hasFlag` uses last-wins across mixed boolean spellings; and `gleann search --help`, `docs/configuration.md`, `docs/api.md`, and `docs/env-vars.md` align supported provider lists with `-tags eif` and `-tags native` caveats.
- **Plugin shutdown now sends a shared `SIGINT` grace period before killing child processes.** `PluginManager.Close()` and `stopPluginLocked()` share one graceful stop path (`10s` default, configurable via `GLEANN_PLUGIN_STOP_GRACE`) across all active plugins in parallel and fall back to immediate `Kill()` when interrupt delivery is unsupported (such as Windows), documented in `docs/env-vars.md`.
- **Tree-sitter AST graph & chunker extraction for Kotlin, Lua, Scala, Svelte, Ruby, and Elixir.** Completes declaration and call edge extraction across those six languages cleanly across chunker and graph indexers, strips parenthesized/negated/nested Elixir `when` guard expressions, module attribute names, and `@spec`/`@type`/`@callback` typespecs from phantom `CALLS` while preserving real compile-time attribute calls, qualified keyword calls, and parenless `|>` pipe targets, and aligns `docs/treesitter.md` and `docs/graph.md`.
- **Memory entity injection batches vector updates once per request with last-wins deduplication.** `EntityService` dispatches non-empty batch updates through `gleann.VectorBatchSyncer` / `LeannSyncer.AddContents` instead of rebuilding the HNSW vector index per entity (1,000 entities -> 1 publication), and deduplicates repeated entity IDs last-wins before filtering empty content in both `EntityService` and `LeannSyncer.AddContents` so cleared duplicates never publish stale text while updating `docs/memory_engine.md` and `docs/plans/005-incremental-vectors.md`.
- **Nested Go submodules and `go.work` workspaces resolve calls and warn clearly on moduleless trees.** `DiscoverModules` loads each nested `go.mod` from its own module root with its real module path (keeping `go.work` scoped to workspaces named via `golang.org/x/mod/modfile.ParseWork` with nearest/deepest element-boundary tie-breaking, and isolating unlisted submodules with `GOWORK=off`), skips ignored `_`/`.` Go fixtures, and reports moduleless `.go` trees cleanly on `stderr`. `golang.org/x/mod` is promoted to a direct dependency in `go.mod`.
- **Builds without tree-sitter emit a non-Go symbol notice across all query surfaces without losing tracking across incremental syncs.** CLI (`explain`, `callers`, `deps`, `path`, `query`), MCP (`gleann_graph_neighbors`, `gleann_impact`), REST (`POST /api/graph/{name}/query`), and A2A now surface the `without tree-sitter` notice accurately when non-Go symbols are queried from a lite build, and `graphstore` applies prefix/exact/set meta mutations deterministically before recomputing `graph_treesitter` inside the same transaction so subsequent Go-only syncs preserve the markers.
- **Benchmark Hybrid rows are labelled with the alpha that ran.** The default hybrid strategy is registered as `Hybrid (default, α=<alpha>)` using the effective weight, `NaN` or infinite weights fall back to 0.7 instead of silently degrading retrieval, and an offline `--compare` accepts strategy names that contain commas and paths that contain parentheses.
- **`make full` builds in Docker without a host Rust toolchain and on macOS.** The build mode is chosen when the Makefile is parsed, the Docker recipe builds `libbitllm.a` and links with `$ORIGIN` run paths, the Darwin branch uses `libfaiss.dylib`, `-lomp` and `install_name_tool`, and `make -n full` no longer deletes `internal/server/dist`. A test checks the prerequisites for each toolchain combination.
- **Retired memory roadmap moved to `docs/releases/`.** `docs/ROADMAP-agent-memory.md` described the removed bbolt/Kùzu/daemon design; it now carries a historical banner, and a doc test rejects those terms in the active docs and the README outside explicitly historical sections.
- **Memory recall graph matches entities and relation types case-insensitively across Unicode.** Searches and relation-type filters use one Go case-folding path, so `istanbul` finds `İstanbul` and `DIYARBAKIR` finds `Diyarbakır`; backfilled seed entities expand to their relations within the node cap, and relation-type deduplication folds case the same way. The recall-graph REST documentation in `docs/api.md` matches the behaviour.
- **Saved onboarding settings `A2AEnabled` and `LlamaCPPConfig` now reach the loaded configuration**, and a test fails when a persisted onboarding field is neither mapped nor allowlisted with a reason.
- **`gleann search --help` lists every flag the command accepts**, checked by a test against the flag table.
- **`gleann index build --help` now lists `--quiet`** with its silence semantics: status lines and the embedded `llama-server` start are silenced, and progress is off unless `--progress` names a surface.
- **The architecture document's file and directory references are validated by a test**, so a renamed path fails the doc check instead of going stale.
- **Long-term memories no longer expire or decay by age.** `ValidityScore()` previously applied a 90-day half-life decay to every tier, so unconfirmed `long` facts dropped below the injection cutoff after ~119 days and were purged by `gleann memory compact`, and `IsStale()` flagged `long` blocks after 180 days. `TierLong` is now exempt from age decay and age staleness while staying mutable via edits, duplicate merges, explicit deletion, suspect marking, caller-set `expires_at`, and Bayesian conflicts.
- **`gleann ask`, chat, and the TUI no longer inject sibling repositories' memories.** Extracted `DetectRepoScope`/`NormalizeGitRemote` into `pkg/memory/scope.go` and wired `InjectRepoContext` into `cmdAsk`, `chat.go`, and `agentchat.go`, matching MCP's repository scope while keeping global blocks and ancestor scopes visible.
- **Sleep-time memory reflection lost conversations, clobbered edits, and reversed confirmations imperfectly.** Mid-cycle conversation updates, retry exhaustion bounds, and same-scope overwrite preservation are handled safely without losing entries behind `lastRun`; `RevertReflection` unwinds multiple confirmations of the same block in LIFO order while preserving subsequent external edits; and CLI/MCP memory inspections format block contradiction notices safely when metadata is nil.
- **Deterministic contradiction detection no longer floods English technical pairs with false positives and handles standard Turkish imperatives.** `ContradictionCheck` requires matching non-empty residuals cleanly, recognizes quoted polarity tokens and signed negative numbers (`-5` vs `5`), folds Turkish diacritics with rune-length bounds (`aç/açma`, `seç/seçme`, `çık/çıkma`, `gör/görme`, `kapıyı`, `dosyayı`), uses Turkish vowel harmony and a closed short-verb lexicon plus English pronoun/article guards (`I hired Al`/`Alma`, `AC`/`ACME`, `dog`/`dogma`), and preserves 2-letter Turkish imperative roots (`at/it/in/as`) without breaking English stop-word filtering.
- **Benchmark Ripgrep baseline file-set parity, old-version fallback, and corpus validation.** `gleann benchmark` invokes `rg -F -c -i` with `--no-ignore-parent` and `--no-require-git` to match `pkg/walker` across git and non-git parents, retries without those compatibility flags on `rg < 12` unknown-flag exit code 2 without swallowing genuine failures, measures retrieved file tokens accurately, and marks missing, moved, or non-directory corpora as unavailable cleanly without `<nil>` strings.
- **Renaming a Go file within its package lost its symbols on the next sync.** The new file's declarations were matched against the old file's rows and then removed with them, so the file stayed dirty and its callers unresolved until a full rebuild. Deleted files are now retracted before changed files are applied.
- **A sync added README, LICENSE and `go.mod` to the code graph** as `block_N` symbols. A sync no longer does, and the first sync with this version removes the rows an older gleann stored.
- **cgo files were left out of exact Go resolution**, in full builds too: `go/packages` reports their generated copies in the build cache, so the files fell back to the syntactic resolver and the package prefix came from a cache path. They are mapped back to their source files.
- **`gleann index remove` deleted any directory named like the index.** `gleann index remove src --index-dir .` removed `./src`, and so did `DELETE /api/indexes/{name}` for a directory of that name under the index directory. The directory is now removed only when it is empty or holds an index: every entry must be a file gleann writes (`<name>.<suffix>`, plus the old unprefixed names) and at least one must be an index file; otherwise the command fails and names the entry it found. Lock files, backups and an old `_graph` directory next to it are still cleaned.
- **`gleann graph build` and `POST /api/graph/{name}/index` wiped the document graph and ran outside the index lock.** A graph build on its own replaced the document nodes with an empty list, so `graph toc` listed nothing afterwards, and it could run while a build or sync of the same index was writing. It now takes the index lock and reads the documents of the source directory, as `index migrate` does (plugin extractors included, so it takes longer on a tree with many documents); when it finds no documents, the stored document graph is left as it is.
- **`gleann graph hook uninstall` deleted the user's own post-commit hook.** gleann appended its section to an existing hook and removed the whole file on uninstall. The section is now between `# BEGIN GLEANN HOOK` and `# END GLEANN HOOK` and only that is removed (a section written by an older version is recognised too); the file is deleted only when nothing else is left. The hooks directory comes from `git rev-parse --git-path hooks`, so worktrees, subdirectories and `core.hooksPath` work, and the hook runs `index sync` instead of a full build.
- **`gleann_gain` always answered zero.** Nothing wrote to the counter the MCP tool reads. Every successful `gleann_shell` and `gleann_read` call now adds the estimated tokens of the raw input (the command output, or the whole file) and of what was returned (about four characters per token). The counter belongs to one MCP server process and starts at zero with it; the tool description and the docs said "across sessions".
- **HNSW: inserting into an imported graph crashed, and `Size()` counted a re-inserted ID twice.** `NewGraphFromTopology` left the random source and the metric name unset, so the first `Insert` hit a nil pointer and float16 vectors of a cosine or inner-product graph were compared with L2.
- **`docs/configuration.md` listed DiskANN keys that do not exist** (`pq_train_size`, `l_search`). The section now shows the real keys, and a doc test compares it with the config struct.
- **Docker images did not build:** `Dockerfile` and `Dockerfile.full` used Go 1.24 while `go.mod` needs 1.25.9. Both now use `golang:1.25.9` and build for the target architecture.
- **A `go install` binary called itself `dev`.** `go install github.com/tevfik/gleann/cmd/gleann@v1.20.1` now reports `v1.20.1` (from the module version in the build info), and `gleann update` compares it with the latest release. A build of a commit between releases or of a modified tree shows its pseudo-version and is still treated as a development build.
- **The code graph of a Go module had no method calls when the installed `go` was older than the module's `go` line.** The exact (go/types) resolver loads the module through `go list`, and gleann ran it with `GOTOOLCHAIN=local`: on a machine whose `go` is 1.22 and whose `go.mod` asks for 1.25, where `go build` works because the go command switches to the newer toolchain in the module cache, the load failed and the build fell back to the syntactic resolver without a word. That resolver cannot follow a call made through a receiver, a variable or an interface, so `gleann graph explain <method>` showed no callers. gleann no longer overrides `GOTOOLCHAIN` (downloads stay off: `GOPROXY=off`), and a build whose exact resolution fails now prints a warning with the reason. This repository, `go` 1.22.2 installed, `go.mod` at 1.25.9: methods with at least one caller 0 of 1,867 before, 1,093 after. Indexes built on such a machine need `gleann graph build <name>`.
- **`gleann index build --dry-run` and the `--max-minutes` gate counted files a build never reads.** The pre-flight estimate walked the directory on its own and skipped only hidden directories, so `node_modules`, build outputs and everything in `.gitignore` / `.gleannignore` were counted (this repository: 11,376 files / 1.5 GB estimated, 1,469 files / 73 MB indexed). It now uses the walk of the build (`gleann.EstimateJobWalk`).
- **`gleann index build` no longer starts on a home directory or a file system root by accident.** `--docs .` typed in the wrong directory read every file below it (hours on a large home). The build now stops before any work and says so; `--yes` indexes the directory anyway.
- **`gleann benchmark` counted its own tasks file as a result and mislabelled the backend.** When the tasks file was part of the index it held every query verbatim and took the first ranks (BM25 Recall@1 was 0 % on such an index); its hits are now dropped, with a note. The vector row is labelled with the backend of the index searched, not the configured default (an HNSW index was reported as "DiskANN+PQ").
- **The retrieval benchmark report claimed a gain whatever the numbers were.** `gleann benchmark` always printed "N x Higher Recall" from Recall@5 of GraphRAG against BM25. It now names the best strategy of each metric (also when that is BM25), says when GraphRAG and Hybrid are identical, and states the weight of one task.
- **Filtered search on DiskANN is now exact for selective filters.** The DiskANN searcher did not implement `VectorDistances`, so selective filters fell back to the approximate widen loop (recall@10 0.824 at 1% selectivity on 100K × 384). It now scores SQL-pre-selected matches from the raw stored vectors (never PQ) on both RAM and memory-mapped load paths: `bench/vectordb/cmd/filtbench`, 1,000 queries, recall@10 and p50, same index before → after: at 100K × 384, 1% 0.824 → 1.000 (123 → 72 ms), 10% 0.982 → 0.9996 (11 → 110 ms: full-table scan over the filter field, as on hnsw); at 10K × 384, 1% 0.901 → 1.000 (102 → 10 ms), 10% 0.843 → 0.9996 (7 → 13 ms); 50% and unfiltered searches unchanged. The recall gate gained a `gleann-search-diskann` row.
- **Filtered search misses true neighbours when a filter matches few passages.** The widen-until-k loop stopped as soon as k candidates passed the filter, but those came from an approximate search over a widened pool, so they were not always the best matches. On a format-2 index whose backend can score explicit IDs (hnsw and diskann with stored vectors), a filter estimated to match at most 12,000 passages and at most a fifth of the index is now answered by scoring all its matches exactly (SQL pre-selection, then vector distances); the estimate is the loop's pass rate times the index size. If the estimate was off (more rows than expected) or the vectors are pruned, the loop widens as before. The pre-selection evaluates the filter on every row (about 60 ms at 100K passages), so this applies to indexes of up to 200,000 passages; larger ones keep the loop's result, with the existing pre-selection fallback when fewer than k results pass. `bench/vectordb/cmd/filtbench`, 100K x 768, default hnsw, 1,000 queries, recall@10 and p50: same index before → after: 1 % selectivity 0.862 → 1.000 (165 → 74 ms), 10 % 0.930 → 0.996 (17 → 112 ms: the price is a full-table scan over the filter field), 50 % 0.989 either way (6.6 → 8.1 ms); at 10K x 384 all rows reach ≥ 0.997.
- **The OpenAPI spec advertised a malformed server URL and left `POST /api/search` untagged.** `servers[0].url` was built as `http://localhost` + the bind address, so a server bound to `127.0.0.1:8081` advertised `http://localhost127.0.0.1:8081` (and `localhost:8081` became `http://localhostlocalhost:8081`), which Swagger UI and Postman then used as the request base URL. A bare `:port` now resolves to `http://localhost:port` and a bound `host:port` is used verbatim. `POST /api/search` gains the `search` tag every other search operation carries, and a test now fails when any operation in the spec has no tag.
- **Configuration and API documentation matched the code again.** `docs/configuration.md` lists the settings-registry keys it omitted (`temperature`, `repeat_penalty`, `max_tokens`, `top_k`, `system_prompt`, `code_embedding_model`, `doc_embedding_model`, `anthropic_api_key`, `server_enabled`, `server_addr`, `mcp_enabled`) with their real defaults, shows the true `llm_model` default (`llama3.2:3b`, not `nemotron-3-nano:4b`), adds the environment-variable layer to the precedence order, says HyDE expansion is off by default, and drops the invented `maintenance_enabled` / `maintenance_interval_h` config keys (those settings are env vars only). `docs/env-vars.md` documents `GLEANN_PLUGIN_TOKEN` and the real `GLEANN_LLM_MODEL` default; `docs/api.md` states up front that its examples assume `gleann serve --port 8080` while the default bind is `127.0.0.1:8081`.
- **`--help` prints usage and exits 0 for every command.** `gleann ask --help` failed with "no question provided", `chat --help` opened the chat TUI, `setup --help` started the onboarding wizard, `graph deps|query|toc|report --help` demanded `--index`, `tokens --help` / `completion --help` treated the flag as a path or shell name, and `service install --help` installed the service. Each now prints its usage, also for `--help=<value>` and before any unknown-flag error. The usage texts were corrected: `ask` lists the rerank, expand, graph and context flags it accepts, `index` documents `--prune` as the HNSW keep fraction, `memory` lists `compact`, `service` lists `--port`, `index sync` lists `--quiet`, and `--modular` is marked as accepted without effect.
- **`ask` no longer puts flag values into the question, and `ask --rerank-pool` works.** The value of a value-taking flag such as `--base-url <url>` or `--index-dir <dir>` was appended to the question; `ask` now skips the values of every value-taking flag it accepts, as `search` does. `--rerank-pool` was accepted but ignored by `ask`; it now sets the rerank pool the same way as in `search`.
- **The A2A agent card advertises a reachable URL, and the documented `a2a_base_url` setting works.** The card's interface URL always had `localhost` in front of the listen address, so `gleann serve` on `127.0.0.1:8081` advertised `http://localhost127.0.0.1:8081/a2a/v1`. The `a2a_base_url` key in `config.json` was documented but ignored, and `GLEANN_A2A_BASE_URL` was used unchecked (a trailing `/` gave `//a2a/v1`). Now a bound `host:port` is advertised verbatim, and a bare `:port` or a wildcard bind (`0.0.0.0`, `[::]`) as `localhost`. The OpenAPI `servers` URL uses the same rule, so it too shows `localhost` for wildcard binds. `GLEANN_A2A_BASE_URL` beats `a2a_base_url`, which beats the derived URL. Both must be http(s) URLs without a user or password (the card is public): a trailing `/` or `/a2a/v1` is removed, an invalid value is skipped with a warning, and the settings screen (Services), where the key now appears, refuses it.
- **The installer prints a working health-check command.** After setup with the REST server enabled, the hint read `curl http://localhost127.0.0.1:8081/health`. With no address saved it suggested `gleann serve --addr :8080`, which is not the default and binds every interface. It now prints `curl http://127.0.0.1:8081/health` and falls back to the real default, `127.0.0.1:8081`.

### Changed
- **HNSW is now the default pure-Go vector backend (replacing DiskANN).** New pure-Go indexes default to HNSW across CLI, REST (`POST /api/indexes/{name}/build` validates explicit `backend` values), and TUI onboarding/settings while preserving stored `meta.Backend` and legacy `diskann_config.use_mmap=false` RAM search for existing DiskANN indexes.
- **`gleann index sync` resolves Go calls with `go/types`, as a full build does.** A sync used the syntactic resolver, so a synced file lost its method calls and interface edges until the next full build. A sync now loads the packages of the changed files, and the packages that declare the interfaces their types implement, and stores the same symbols and edges as a full build of the same tree (on this repository: equal checksums over all 11,850 symbols and 47,365 edges after an edit, and again after a second one). A file synced while its package did not type-check is resolved again by the next syncs until it does. Cost: the graph step of a one-file sync goes from about 0.13 s to 0.34-1.16 s. Without a `go` toolchain, or when the load fails, the sync warns and stays syntactic; `GLEANN_GRAPH_EXACT=0` turns exact resolution off. One limit: a new type that implements an interface of a package it does not import gets that IMPLEMENTS edge at the next full build or `gleann graph build`.
- **Faster lexical staging, Go AST extraction, and ignore-pattern matching with bit-for-bit identical indexes.** `Analyzer.TokenString` writes lowercased ASCII tokens directly into a preallocated buffer without slice/join churn, passage storage extracts `source` without marshaling discarded metadata (`itemSource`), Go graph extraction parses each file once with `parser.SkipObjectResolution`, and `pkg/walker` precompiles ignore patterns into exact/prefix/suffix/glob kinds. Measured via `bench/vectordb/cmd/corpusbench` with identical SHA-256 hashes across all 14 SQLite tables: corpus with graph 9.70 s → 7.49 s (−22.8%), without graph 20.31 s → 13.00 s (−36.0%); independent 13,896-passage Go tree 3.90 s → 2.12 s with allocations 856 MB → 407 MB.
- **`deps/` is no longer tracked in git** (a prebuilt FAISS for one platform, 16 MB): build it with `scripts/build-faiss.sh`. `chromem-go` is no longer a dependency of the root module; the comparison with it moved to `bench/vectordb/competitive`. The unused `deps.txt` is gone, and a `.gleannignore` keeps generated files out of an index of this repository.
- **HNSW builds about twice as fast, same index.** The node table is a dense slice with a map for sparse IDs, the visited set and the search buffers are reused instead of allocated per insert (130 allocations per insert became 5), and each link keeps the distance it was made with, so pruning a full node no longer measures its whole list again. `idx.index` and every search result are bit-identical to the previous build (checked by checksum for L2, cosine and inner product, and by a reference implementation of the old algorithm kept in the tests). Vector build of 20,000 x 384: 15.6 s -> 7.5 s; 5,000 x 768: 6.45 s -> 3.21 s.
- **DiskANN builds: 3.7x faster, higher recall.** Nodes keep up to 1.3 x R neighbours during the build and are pruned to R once at the end (the degree slack of the Vamana paper), which saves most of the re-pruning of full nodes. 100K x 768, 4 CPUs: build 6,489 s -> 1,773 s, recall@10 0.878 / 0.965 / 0.989 -> 0.920 / 0.981 / 0.994 at search L 64 / 128 / 256. A best-first beam for the build search was tried and rejected: it was faster (782 s) but scored 0.512 at L 64 on the same data, so the build keeps its insertion-order walk. The loss is invisible at 10K vectors and on real 384-dimension embeddings, so `bench/vectordb/gate` now holds DiskANN to 0.98 recall at 10K.
- **DiskANN `search_l` scales with the index when unset.** Zero (the default) now means 100 up to 25,000 vectors and 100 x sqrt(n / 25,000) above, capped at 512; a set value is used as given. 100K x 768: auto L = 200, recall@10 0.991 at 9.5 ms p50 (L 256 fixed: 0.994).
- **DiskANN builds: PQ training runs in parallel.** The sub-quantizers' Lloyd iterations run on all CPUs; their starting centroids are still drawn in order from one generator, so the codebook is bit-identical. PQ training was 46 % of a 5,000-vector build.
- **Faster index builds, same index.** The HNSW build measures distances to several neighbours at once (four independent accumulations, each summed in the same order as before, so every distance, the graph and `idx.index` are bit-identical), and the lexical staging of a new index commits once instead of once per source file. Measured with a lookup embedder, 20,000 passages of 384 dimensions, 4 CPUs: HNSW vector build 40.5 s to 30.0 s, passage staging 4.1 s to 2.3 s, total 44.6 s to 32.4 s (v1.9.0: 34.4 s). `bench/vectordb/cmd/buildbench` is the harness.
- **Release workflow:** a re-pushed tag now also replaces the release notes with the tagged `docs/releases/<tag>.md` (the upload action kept the old body).
- **Dead code removed:** `Runner.TaskRecords` in `pkg/benchmark` had no callers and is gone; `deadcode -test ./...` (with and without `-tags treesitter`) reports no unreachable functions outside `tests/e2e/fixtures/` and build-tag-guarded symbols.

## [v1.20.1] — 2026-11-20

See [docs/releases/v1.20.1.md](docs/releases/v1.20.1.md).

### Added
- **`bench/vectordb`, a vector database benchmark (RFC 006, step 1).** A nested Go module, outside the root `go.mod`, that measures stores on deterministic synthetic data against brute-force ground truth: bulk load, cold start, recall@10 and latency over a search-width sweep at concurrency 1 and 8, filtered search at 1/10/50 % selectivity, a one-file update, and disk and memory footprint. It has adapters for gleann's own `hnsw` and `diskann` backends, which search as gleann does; candidate databases come in later steps. Run it with `make bench-vectordb`.
- **`bench/vectordb -dup`** replaces a share of the vectors with near-copies of 20 base vectors, the data on which graph indexes starve (license headers, boilerplate, repeated table text).

### Changed
- **Memory search has a retrieval floor.** A block now matches only if it contains the query verbatim or enough of its topic words (`min(2, ceil(0.35 * n))` of the n query words, question words and the default labels not counted; hits below 25% of the best are dropped), so a small or unrelated store returns nothing instead of one-word matches that were injected into prompts. On a labelled set of 62 memories and 37 queries, the blocks returned fell from 432 to 44 (precision 0.07 → 0.68) with the same recall (30 of 32 expected blocks); queries with no relevant memory returned 93 blocks before and 1 now. `GLEANN_MEMORY_SEARCH_FLOOR=off` restores the old behaviour.
- **Memory writes merge near-duplicates.** The same fact written again with different case, whitespace, punctuation or a few extra words reinforces the existing block of the same scope and tier (`Confirms`+1) instead of adding another; when the new text only adds words, it replaces the stored text. Texts that swap one entity for another ("the billing service …" vs "the auth service …"), negations, differing numbers and failure blocks are never merged. Blocks stored under the old IDs are still found; no migration. `GLEANN_MEMORY_NEAR_DEDUP=off` keeps only exact (normalised) duplicates merging. A sleep-time reflection that merges into an existing block no longer records it as added, so reverting the reflection cannot delete the pre-existing block.

### Security
- **The `openai` provider never falls back to OpenAI's cloud, and each provider gets only its own endpoint and key.** gleann now sends data to api.openai.com only when that URL is set (`openai_base_url`, `--openai-base-url` or `OPENAI_BASE_URL`); without an endpoint, chat, embeddings, summaries and model listing fail with `openai endpoint not set` before anything is sent. The leaks this closes:
  - **Embeddings:** an OpenAI-compatible URL on port 11434 (Ollama's own `/v1` API) was rewritten to `https://api.openai.com`, so the whole corpus went to OpenAI's cloud.
  - **Embeddings:** an empty `openai_base_url` also defaulted to the cloud.
  - **Chat:** `gleann chat`, the TUI chat and HyDE expansion used `ollama_host` as the OpenAI endpoint and sent the OpenAI key to it.
  - **REST:** `POST /api/indexes/{name}/ask` with `"llm_provider": "openai"` kept the Ollama host and sent `OPENAI_API_KEY` from the environment to it.
  - **Proxy and A2A:** a stored OpenAI key alone switched the OpenAI-compatible proxy and A2A to the `openai` provider.
  - **Other keys:** Anthropic, Gemini and `memory` summaries were given the OpenAI key.

  One resolver (`gleann.Config.ChatEndpoint` / `EmbeddingEndpoint`) now serves the CLI, TUI, REST, MCP, A2A and the proxy. `openai_base_url` may end in `/v1` (it was doubled to `/v1/v1/...`). `gleann doctor` reports a missing endpoint and marks OpenAI's cloud.

  **Upgrade:** if you use OpenAI's cloud without `openai_base_url`, run `gleann config set openai_base_url https://api.openai.com/v1`.

### Fixed
- **`POST /api/config` with a partial body reset every other setting.** The body was decoded into an empty config, so `{"llm_model":"m2"}` also cleared `index_dir`, the Ollama host, API keys and the HNSW settings (an empty HNSW section builds without the neighbour heuristic), and saved that to `config.json`. The body is now applied on top of the running config; fields it leaves out keep their value and `""` still clears a string. To clear a value the key must be in the body (a Go client that marshals `gleann.Config` drops empty `omitempty` fields and has to send the key itself). The web UI uses `/api/settings` and was not affected.
- **A zero `gleann.Config` built a poor index.** Library callers that passed `gleann.Config{IndexDir: …, Backend: …}` instead of starting from `DefaultConfig()` got an HNSW graph without the neighbour heuristic (`UseHeuristic` is a bool, so zero means off) and searches with `ef` equal to top-k; on 100K × 768 vectors recall@10 was 0.878 instead of 0.995. `NewBuilder` and `NewSearcher` now fill index settings left at zero (an all-zero HNSW or DiskANN section gets the defaults; a partly set one keeps its choices, an explicit `use_heuristic: false` included). The CLI, TUI, MCP server and web UI already started from the defaults.
- **HNSW: nodes among near-duplicate vectors kept too few neighbours.** When the diversity heuristic picks fewer than M neighbours, the slots are meant to be filled with the closest remaining candidates, but that top-up required leftover candidates, which the heuristic never leaves when it stops short of M, so it never ran. Among near-copies (boilerplate, license headers, repeated table or chart text) the heuristic rejects almost every candidate: on 10K × 384 vectors with 60% near-copies of 20 base vectors, 79% of nodes had fewer than 32 level-0 neighbours, some only one, and recall@10 was 0.681 at ef 16. With the top-up every node keeps at least 32 and recall@10 is 0.911 (0.952 → 0.992 with 30% near-copies). Data without near-copies is barely affected: on 10K × 384 vectors the graph is the same; on 100K × 768, recall@10 rose from 0.828 to 0.849 at ef 16 and from 0.958 to 0.966 at ef 32, for 1.2% more build time and 0.3% more disk (bench/vectordb). On near-copy data the build takes about twice as long, because the graph is no longer starved of edges (`vectorbench -dup 0.3`: recall@10 0.920 → 0.963 at ef 16). Nodes added from now on get the top-up; `gleann index rebuild <name>` rebuilds an existing HNSW graph with it.
- **HNSW: `SearchWithRecompute` could crash on a neighbour missing from the graph.** The upper-level greedy step moved to such a neighbour and then read its nil node. Missing neighbours are now skipped at every level, as `Search` does, and are not recomputed.
- **Keyword search dropped the subject words of small indexes.** The FTS5 leg drops query words found in more than 20% of an index's passages. In an index of one document those are its subject (the law's or the product's name), which questions name: "In NIST SP 800-53 Rev. 5, what is the name of control AC-11?" was searched as `what name`. The cut now applies only to indexes of 10,000 passages or more, where it keeps queries fast (synthetic corpus, p95 without the cut: 20 ms at 10K passages, 200 ms at 100K; 22 ms at 100K with it). On 18 PDFs indexed one per index, 34 questions, the answer reached the LLM for 30 questions with the cut and for 31 to 33 without it (hybrid alpha 0.3). The retrieval quality gate (8,525 passages) is unchanged.
- **Turkish: the case suffix after an apostrophe became a search term.** "İş Kanunu'na göre" was searched as `kanunu`, `na`, `göre`, and `na` matched unrelated passages. In Turkish indexes the suffix after an apostrophe (`'` or `’`) that follows a letter or digit is now dropped from passages and queries ("Kanunu'na", "AB'ye", "2023'te" become "kanunu", "ab", "2023"); a capital after the apostrophe ("O'Brien") is kept. A Turkish index rebuilds its keyword table once, from the stored text, on its first search after the upgrade; nothing is re-embedded, and indexes in other languages are not touched.
- **`POST /api/indexes/{name}/search` and `POST /api/search` ignored `"hybrid_alpha": 0`.** Keyword-only search was reachable only through the proxy header. `0` now searches lexically only (the query is not embedded), an absent field keeps the configured weight, and a value outside `[0, 1]` answers 400.
- **The proxy dropped indexes it could not search without saying so.** With several indexes, one in the old store format, missing, or failing to load was left out silently, so the LLM answered without its documents. It is still left out, but now logged, and a pass-through reply lists it in `X-Gleann-Skipped-Indexes` (percent-encoded JSON `[{index, reason}]`; the reason has no file paths). A private index is left out and only logged.
- **`gleann index migrate` refused a correctly copied index whose passages have many near-copies.** The self-check expects each of 20 sampled passages among the top 10 lexical hits for its own text. In a PDF with charts, a passage of tick labels ("1 2 3 ... 64 Layer 9") has ten or more siblings that repeat the same words and outrank it, so the check failed (`passage N is not its own top-10 lexical hit`) and the index could not be migrated; without its source files it could not be rebuilt either. Such a passage now passes when its row holds its text and its lexical row contains every one of its query terms; a passage copied to another row, or whose lexical row belongs to another passage that shares only a few words, is still refused.
- **A2A: a task in `INPUT_REQUIRED` could not be resumed.** The task state machine moved to `WORKING` only with the `start` trigger, which `INPUT_REQUIRED` refuses; it now uses `resume` there.
- **DiskANN: recall@10 capped near 0.91.** The searcher reranked only the first 2×top-k candidates by PQ distance with exact distances, and `search_pq_rerank` was ignored on the default search path. PQ misorders close neighbours, so raising `search_l` did not help: recall@10 stayed at 0.91–0.93 on 10K × 384 vectors and at 0.65–0.67 on 100K × 768 for any L from 64 to 256. The default now reranks all `search_l` candidates, and `search_pq_rerank` sets the width on both search paths. Recall@10 on 10K × 384 at `search_l` 100: 0.919 → 0.998. On 100K × 768: 0.651 → 0.880 at L 64, 0.669 → 0.968 at L 128, 0.672 → 0.990 at L 256, with the same latency at the same L (bench/vectordb, synthetic data). On large indexes, `search_l` 128–256 reaches 0.97–0.99. On indexes built with pruned embeddings, a wider rerank means more re-embedding per query; `search_pq_rerank` lowers it.
- **Upload on Windows: a file name that reduces to nothing (`..`, `/`, `\`) gave 500 instead of 400.** `filepath.Clean("/..")` is `\` on Windows, which slipped past the check; the name is now cleaned with slash-only `path`.
- **Code graph: split and phantom symbols (#12).** A function the chunker cut into `Name_partN` passages for search became several graph symbols (3,570 `_partN` symbols on this repository's own graph, 3,262 with tree-sitter); it is now one symbol per declaration, spanning the whole declaration, and its calls and callers attach to it. Passages for search are unchanged. Call, reference and implements targets that lie inside the indexed module but are not a declared symbol (builtins, conversions, locals, guessed names such as `cmd/gleann.len` or `graphstore.int64`) were stored as edges marked external, 8,184 edges to 1,074 in-repo phantom nodes (9,409 and 1,813 with tree-sitter); they are now dropped, so `dst_external` is set only for import-anchored standard-library and third-party targets. On the same repository: 0 `_partN` symbols, 0 in-repo phantom nodes, every edge into a declared symbol kept (callers of `filepath.Join` unchanged), and about 3,200 real edges gained because split functions now resolve. A call to a function that is declared nowhere yet is no longer remembered as an external edge, so such a call is linked only when its target exists at the time of the sync that sees the call.

## [v1.20.0] — 2026-11-17

See [docs/releases/v1.20.0.md](docs/releases/v1.20.0.md).

### Breaking changes
See [docs/releases/v1.20.0.md](docs/releases/v1.20.0.md) for the upgrade steps and [docs/decisions/kuzu-to-sqlite.md](docs/decisions/kuzu-to-sqlite.md) for why Kùzu was removed.

- **Format 2 is the only index format (RFC 004 B1, B2).** Every new index is one SQLite database `<name>/<name>.db` (passages, FTS5 lexical index, manifest, code graph); the lexical leg is always the persisted FTS5 index with AND-first queries and a document-frequency cut of 0.2. The switches `GLEANN_STORE_FORMAT`, `GLEANN_LEXICAL` and `GLEANN_LEXICAL_OPTS` are removed: a value still set is ignored and every command prints one line, `notice: <names> ignored: removed in gleann v1.20 (every index is format 2 with FTS5 lexical search)`. The in-memory BM25 leg and its fallback are gone (a custom `SetScorer` still works); the retrieval-quality gate moves to the format-2 numbers (BM25 MRR 0.521, dense 0.297, hybrid 0.376; the in-memory BM25 measured 0.530 / 0.381).
- **Indexes built by gleann v1.9 or earlier must be migrated (RFC 004 B2, B3).** v1.20 does not read the old store format (bbolt `<name>.passages.db`, `<name>.lex.db`, Kùzu `<name>_graph`): search, ask, chat, sync, watch, info, repair, storage, tag, set, build, the graph commands, REST, MCP and A2A stop with `index X uses the old store format; run: gleann index migrate X`. `gleann index list` marks such an index, and `gleann index remove` and `gleann index rebuild` still work on it.
- **`gleann index migrate <name>|--all [--graph] [--cleanup]`** converts an old index without re-embedding: passages are copied with their vectors reused, passage IDs with gaps are renumbered (the main vector file is rebuilt from its stored vectors; a pruned index is pointed at `index rebuild`), the lexical index is built with the same analyzer as a fresh build, `<name>_memory_vectors` is converted too, and the code graph is rebuilt through the normal document pipeline from the index's source directory when the old index had `<name>_graph` (or with `--graph`). The old files stay until `--cleanup`, which deletes them and prints each path; `gleann doctor` lists them. `--rollback` and `--language` are removed. The migrate command is kept for v1.20.x and removed in v1.21.
- **Kùzu is removed; the code graph is SQLite in every build (RFC 004 A3).** gleann no longer depends on `go-kuzu`/`libkuzu` (the full build ships no `libkuzu`), and `-tags treesitter` only adds the tree-sitter parsers. The code graph lives in the index database `<name>/<name>.db` and works in every build, including `go install`, `CGO_ENABLED=0` and Windows. An old `<name>_graph` Kùzu directory is never read: `gleann index migrate` rebuilds the graph from the sources, and `gleann index migrate --cleanup` and `gleann index remove` delete the directory. `GLEANN_KUZU_AUTOREPAIR` is gone; the `module` field of `POST /api/graph/{name}/index` is accepted and ignored. The MCP graph tools (`gleann_graph_neighbors`, `gleann_impact`, `gleann_document_links`, `gleann_graph_stats`, `gleann_symbols_in_file`, `gleann_document_toc` and the four analysis tools) are always advertised and work in the pure-Go build too. The memory vector syncer (`<name>_memory_vectors`) runs in every build, `CGO_ENABLED=0` included. Memory entities of old `<name>_memory` Kùzu stores are carried over with `kuzu-memory-export` (a separate module, prebuilt for linux/amd64, linux/arm64 and darwin/arm64 in the release assets) and `gleann memory import-graph`.
- **Raw Cypher is removed from the REST API and the UI.** `POST /api/graph/{name}/query` with `type: "cypher"` answers 400 `raw Cypher was removed; use callers/callees/symbols_in_file/impact`, and the Graph page no longer offers it; the typed queries stay, and `gleann graph export --format cypher` still writes Neo4j statements. `GET /api/graph/{name}` of an index without a code graph is 404 (it answered `available: true` with zeros because opening the path created an empty Kùzu database), and `toc` of a path that is not an indexed document is 404 (it was a 500).
- **Memory moves to SQLite** (`~/.gleann/memory/memory.sqlite`, details under Storage engine). **After the first open, older gleann binaries on the same machine get an error on memory commands: update every installation together.**
- **`gleann index rebuild <name>` no longer needs `--docs`**: it takes the source directory recorded in the index and keeps its tags, description, MCP exposure, embedding model, backend and code graph unless a flag overrides them.
- **The REST server indexes or reads directories on a client's request only inside `allowed_roots`** (default: your home directory); see Security. Servers that index directories outside the home directory through the API need `allowed_roots` set.

### Fixed (Windows, macOS and CI)
- **Windows: incremental updates and merges failed while `serve` (or any reader) had the index open.** A publication renames `<name>.index.tmp` over `<name>.index`, which Windows refuses while the file is mapped or open. The memory-mapped HNSW and DiskANN readers now load a private copy on Windows and close the file at once (an open index costs its file size in RAM there; Unix keeps the shared mapping).
- **Windows: every sync re-read files in subdirectories, and their old passages were not removed.** Passage sources were stored with backslashes on some extraction paths, so they never matched the slash-separated manifest. Sources are stored with forward slashes on every path; a sync also removes the backslash form an older index may hold.
- **Windows: "connection refused" from Ollama was not recognised** (Windows words it "actively refused it"): embedding, chat and the retry policy now classify the error by errno, so the "is it running?" hint and the retry work there too.
- **Windows: a conversation store or index directory that is a regular file was reported as empty** instead of an error.
- **Windows: the plugin settings binary was not found in the plugin directory** without its `.exe` suffix.
- **A searcher loaded twice leaked the first passage store handle**, and a failed Load could leave it open.
- **`serve` left the memory database and other server resources open when it failed to start** (port in use, refused bind).
- **REST: a search whose index load was invalidated on every attempt (config updates in a row) answered 404 "not found"**; it is now 503 with `Retry-After: 1`.

### Security
- **The REST server no longer indexes or reads arbitrary directories on a client's request.** `index-path`, `update` (`docs_root`, `sources`), `watch` (`dir`), graph `docs_dir` and the A2A multimodal file path must lie inside `allowed_roots` (new setting, or `GLEANN_ALLOWED_ROOTS`; default: your home directory), otherwise the server answers 403. Paths are resolved through symlinks before the check. The command line is not restricted. Servers that index directories outside the home directory through the API need `allowed_roots` set.
- **MCP file tools stay inside the project.** `gleann_read_full_document` reads only inside the index's source directory; `gleann_read` reads inside the agent's working directory (unless that is a file-system root or the home directory) and the source directories of the exposed indexes; `gleann_sync` keeps `docs_dir` and `files` inside the allowed roots or the source directory. A refused path gets the same answer as a missing file.
- **Plugins get a bearer token.** gleann creates a token per plugin on first launch, keeps it in `<gleann home>/auth/plugins/<name>.token` (0600, shared by all gleann processes), passes it to the plugin as `GLEANN_PLUGIN_TOKEN` and sends it as `Authorization: Bearer` on every request except `/health`. A `token` in `plugins.json` overrides it (for plugins started by hand). Plugins that do not check tokens keep working.
- `/api/proxy/models` no longer follows client-supplied loopback, private or link-local hosts, or redirects to them; the configured Ollama and OpenAI-compatible hosts stay reachable, and a configured host may not redirect to another host. `GLEANN_MODEL_DOWNLOAD_ALLOW_PRIVATE=1` lifts the guard.

### Storage engine (RFC 003, RFC 004, RFC 005)
- **Persisted lexical index.** The lexical leg is a SQLite FTS5 index on disk instead of the in-memory BM25 that every cold open rebuilt. Measured at 100K passages (same binary): first query of a running server 4.5 s → 0.3 s, server memory 1.2 GB → 0.4 GB. AND-first queries and a document-frequency cut of 0.2 remove the latency tail (warm p95 135 → 55 ms) and keep the retrieval-quality gate within tolerance (BM25 MRR 0.521 against 0.530).
- **One SQLite database per index.** Every index is `<name>/<name>.db`: passages with stable IDs, the lexical index, the file manifest and the code and document graph, written one transaction per source file, with crash-safe vector publication. At 1M passages: warm search p50 0.9 s → 47 ms, p95 1.2 s → 110 ms, first server query 35 s → 3.6 s, server memory 8.8 → 1.4 GB, index 2.46 → 1.97 GiB. Build time is about 10-18 % longer. An older gleann that syncs a migrated index rebuilds it in its own format from the sources.
- **Incremental vector updates (format 2).** A sync adds, changes or removes a file without rewriting the vector index: new passages go to a small exact-search delta file next to it, removed ones become dead slots, and a merge or compaction rebuilds the index from the stored vectors (no re-embedding of unchanged text) when the delta passes max(4096, 2 %) of the passages or 5 % of the slots are dead. At 100K passages a one-file sync takes 0.3 s against a 126 s build and a no-op sync 0.09 s; running servers and MCP sessions pick the change up without a reload. Tuning: `GLEANN_DELTA_MIN`, `GLEANN_DELTA_SHARE`, `GLEANN_DEAD_SHARE`, `GLEANN_DEAD_MIN`.
- **Memory moves to SQLite** (`~/.gleann/memory/memory.sqlite`). The first open copies `memory.db` under a lock, verifies the counts, keeps the old file as `memory.db.v1` and leaves a guard file, so several agent processes can now write memory at once. Older gleann binaries on the same machine get an error on memory commands after that (see Breaking changes).
- **One build or sync per index across processes.** Build, sync, repair and watch take the index lock `<IndexDir>/<name>.lock` (the one `index migrate` takes) for the whole operation. A second gleann process that builds, syncs or migrates the same index stops at once with a message naming the index; `index build --watch` keeps the changes and retries on the next change. Before, only bbolt's file lock kept two writers apart.
- **The memory entity graph works in every build.** `inject_knowledge_graph`, `delete_graph_entity`, `traverse_knowledge_graph` and `/api/memory/*` keep their entities in `memory.sqlite` (tables `entities`, `relations`, `entity_archive`, one namespace per index) instead of a Kùzu database per index, so they also work in the `go install` build and on Windows. Traversal keeps the depth cap of 10 and no longer slows down on densely linked entities. Entities stored by v1.9.x in an old `<name>_memory` Kùzu store (a single file; it is not a directory) are carried over with the separate `kuzu-memory-export` tool (`make kuzu-memory-export`) and `gleann memory import-graph <file.json|dir>`, which keeps ids, attributes, timestamps and the archive and is a no-op the second time; gleann logs the two commands once per process and `gleann doctor` lists unimported stores. The old store is never modified.
- `gleann memory import-graph` also adds the imported entities to the namespace's memory vector index (`<name>_memory_vectors`) when an embedding model is configured, as the server's memory syncer does for injected entities.
- **Failure memory.** `gleann memory failure add --command <c> --error <text> --fix <text> [--path p]... [--symbol s]...` and the MCP tool `memory_failure_add` record a command that failed and the fix that worked. The same failure recorded again (error text differing only in paths, line numbers, addresses or timestamps) confirms the existing record instead of adding one. `gleann memory context --command <c> --path <p>` and MCP `memory_context` with `command`/`paths` add the matching failures in their own section, inside the injection budget; `gleann memory failure list` shows them all. `memory_failure_add` is in the `core` MCP profile.
- The embedding cache writes each batch of vectors before computing the next, so a build stopped halfway keeps the vectors it already computed.
- **The code graph lives in the index database and works in every build.** `index build --graph` and `index sync` write symbols, edges and document nodes into `<name>/<name>.db` (one transaction per changed file; a file whose graph write fails keeps its old hash and is retried by the next sync), and `gleann graph deps|callers|explain|path|query|toc` and the MCP graph tools read it, also in the pure-Go `CGO_ENABLED=0` binary. Without tree-sitter the graph comes from `go/ast` (Go files: calls, implements, references; other languages: declarations only). `internal/analysis` (the tokenizer, with Turkish folding for Turkish prose and CJK bigrams) is not yet used.
- **Faster bulk load and a smaller code graph (RFC 004 E).** Edge endpoints are integer node ids, edge kinds and confidences are interned, and `graph_edges` is a `WITHOUT ROWID` table keyed by `(src, dst, kind)`; a read-only `edges` view keeps the old text shape. Synthetic graph with 1M CALLS edges (`bench/graphdb`, cores 0-3): bulk load 7.28 → 3.77 s, disk 183.8 → 75.3 MiB, callers depth 3 0.71 ms, impact depth 3 0.73 ms, shortest path 2.61 ms, symbol search 1.47 ms, one-file update 102 ms; at 100K edges load 339 ms and 8.0 MiB. On this repository (12,224 symbols, 35,620 edges) the graph build goes 1.27 → 0.85 s and the graph tables 16.9 → 7.8 MiB. An existing graph is converted in place by the schema step `graph_ids` on first open, without re-extraction (7 s at 1M edges). A graph rebuild reclaims free pages before the WAL is checkpointed, so it no longer leaves a database-sized WAL file next to the index.
- **Graph analysis works on the SQLite graph in every build.** `gleann graph viz|report|communities|export|wiki|hook|map|risk`, the MCP tools `gleann_communities`, `gleann_risk_analysis`, `gleann_repo_map` and `gleann_navigate_symbol`, `GET /api/graph/{name}`, `POST /api/graph/{name}/query|index`, `/toc`, `/documents` and the A2A skills (communities, repo map, risk) read the SQLite graph, also in the pure-Go `CGO_ENABLED=0` binary. Without tree-sitter, only Go files have call edges, so for other languages the analysis rests on declarations. Community detection, PageRank, risk, repo map, export and viz are now deterministic (before, the same Kùzu graph gave different community counts, ranks and edge directions from run to run). Compared with the Kùzu answers: no phantom nodes for standard-library and built-in calls (not fully true in v1.20.0: files without exact resolution still produced in-repo phantom targets such as `pkg.len`, 178 built-in-named nodes on this repository, until #12 was fixed), method calls between Go methods are found (`main -> Service.Report`), and a Go declaration is anchored at its `func` line, not its doc comment.
- **Exact Go call resolution in the code graph.** When the indexed tree is a Go module that type-checks, a full build resolves CALLS with `go/types` (interface dispatch, promoted/embedded methods, aliased and dot imports, generics and method values; a shadowed local no longer resolves to the package-level function) and adds IMPLEMENTS edges from method sets, labelled `confidence='exact'`; standard-library/third-party callees stay external. Packages with type errors, trees without `go.mod`, cgo-only/build-tag-excluded files and incremental syncs keep the syntactic `go/ast` resolver, and no load failure aborts the build. On gleann's own tree the full graph build goes ~1.8 s → ~3.8 s and caller recall over 20 sampled functions rises 0.948 → 1.000 (precision ~0.99). It needs a Go toolchain and never downloads modules or edits `go.mod` (`GOPROXY=off`, `-mod=readonly`, two-minute bound). `GLEANN_GRAPH_EXACT=0` forces the syntactic resolver.
- **Call graph of Python, JavaScript, TypeScript, Rust, Java, C, C++, C#, Ruby, PHP and Swift sources (`-tags treesitter` builds).** `index build --graph` and `index sync` now extract tree-sitter CALLS into the SQLite graph (before, only the Kùzu path had them). A call is charged to the method that makes it (the Kùzu path charges the class), calls at the top level of a file to a per-file `<script:file>` symbol anchored at line 1, and a call to a method of the same package binds to it (`inferred`, or `ambiguous` with several candidates). A lite build still gives declarations only for these languages. A full build extracts files on `NumCPU` workers: 587 Python files of the standard library took 4.2-7.7 s serial and 1.4-1.5 s now (Kùzu path 1.6-1.8 s); an incremental sync re-extracts unchanged files whose calls a new declaration resolves.

### Fixed
- **An uploaded document lives only in its index.** `POST /api/indexes/{name}/upload` builds ran with the vault tracker (recording the deleted temp folder) and wrote every passage vector to `~/.gleann/cache/embeddings`, so deleting the index left traces. Upload builds now skip the vault and use a memory-only embedding cache (`CacheOptions.MemoryOnly`, `indexing.Options.NoEmbeddingDiskCache`); at start the server prunes the vault records of past upload folders (`Tracker.RemovePathsWithPrefix`, temp path normalised through symlinks, case-insensitive on Windows).
- **A long build keeps its answer.** The HTTP write timeout is `max(30 min, GLEANN_TIMEOUT_BUILD_S + 5 min)` instead of a fixed 30 minutes, so a build limit above 25 minutes no longer ends with a dropped connection.
- `search --explain` shows the per-term breakdown for the FTS5 lexical scorer, `gleann info` and the storage inspection count `<name>.db` (and its -wal/-shm), and `index storage --set` backs up and restores the database with its WAL files.
- Adding to an index that does not exist now fails with a typed `index not found` error, and opening its passage store no longer creates an empty directory; the missing-index case is told apart from an index of the old store format (`gleann.DetectStoreFormat`).
- **A running server, MCP server or chat sees another process's sync.** A cached searcher kept its vector index and resolved renumbered passage slots against it, so after a `gleann index sync` in another terminal a running `serve` could return the wrong passage text. Acquiring a searcher now compares the published vector generation and the graph state with the loaded one (one small read, no file walk) and reloads on a change; a search that straddles a publication returns `index changed while searching` (the REST search retries once) instead of a wrong passage, and a graph built after the server started is picked up.
- **A rebuild keeps the code graph.** A lexical-only sync and `index build` without `--graph` deleted `<name>.db`, which also holds the graph, so the callers of every unchanged file were lost. The passages, the lexical index and the file manifest are now replaced inside the existing database in one transaction: a file that disappeared loses its symbols and edges in the same commit, a file whose content changed is marked for the next graph pass, and no database file is deleted while a server or another process has it open (Windows refused that). A database that cannot be opened (damaged, or written by an incompatible build) is still recreated, and then the graph is rebuilt from the sources, with a message.
- **Filtered search returns k results.** Metadata filters (`metadata_filters` in REST, `filters` in MCP, `WithMetadataFilters` in the API) were applied after the top-k retrieval, so a selective filter returned far fewer than k results although k passages matched (a filter matching 3% of the corpus returned ~2 of k=10). The candidate pool now widens until k results pass the filter, sized from the observed pass rate and capped at 4096 candidates, on the vector, lexical and hybrid legs; when the cap is reached short of k, a format-2 index pre-selects the matching IDs in SQL (no passage text read, at most 50,000 rows) and scores just those. A vector backend that cannot score given IDs (memory-mapped HNSW, DiskANN) keeps the matches the loop found and fills up behind them with the pre-selected passages that match the query words. A passage scores the same with and without a filter that keeps it (the vector score normalizer is fixed to the first candidate pool), the pre-selection fallback applies the same `min_score`, kind and ranking boosts as the main path, and filter field names are bound as SQL parameters, never interpolated into the statement. Unfiltered search is unchanged. Cost per query on a synthetic index (mock embedder, k=10), unfiltered / 3% / 0.01% filter: 24 / 55 / 261 ms at 20K passages, 256 / 503 / 521 ms at 200K.
- **`go install github.com/tevfik/gleann/cmd/gleann@latest` works** (from the next release on). `modules/bm25`, `chunking`, `diskann` and `hnsw` are packages of the root module and the root `go.mod` has no `replace` directives; `modules/settings` stays a separate module because the plugins import it.
- **A malformed `~/.gleann/config.json` is no longer ignored.** Commands stop with the file path and the line and column of the JSON error; the file is never rewritten. `version`, `help`, `config path|edit|validate`, `setup`, `doctor`, `completion` and `update` still run, and `config validate` and `doctor` report the error.
- **`gleann search` and `gleann ask` reject unknown flags** (exit code 2, `unknown flag --x`, with a suggestion for near misses); `--` ends flag parsing. The values of `--doc-model`, `--backend` and about a dozen other flags no longer leak into the search query.
- **Every command rejects unknown flags** (exit code 2 with a "did you mean" hint), not only `search` and `ask`; use `--` to pass text that starts with dashes to `memory remember|add|forget|search` and `config set`. `memory search --json` no longer puts `--json` into the query.
- **`--flag=value` works like `--flag value`.** Before, it was accepted and silently ignored (`search --top-k=2` returned 10 results; `index set x --mcp=true` did nothing).
- `gleann search --help` shows the real `--top-k` default (10), and the saved `top_k` setting now applies to CLI commands (`--top-k` still wins).
- The generated AGENTS.md and SKILL.md list only the MCP tools of the default profile and say how to enable the full set (`gleann mcp --tools full`).
- **The text chunker splits text without sentence punctuation or spaces** (logs, minified text, CJK) at the size limit instead of producing one huge chunk; `。！？` end a sentence, and a single paragraph longer than the chunk size is split by sentences. On gleann's own documentation the passage count changes from 662 to 663.
- **`index sync` no longer deletes the only good copy of an index after a killed rebuild.** A leftover `<index>.sync-bak` is restored (or discarded when the index is complete), and a cross-process lock keeps a second gleann away from an index that is being rebuilt. `gleann index list` and `gleann doctor` report a pending rollback copy.
- **`index watch` updates go through the same path as `index sync`**: the recorded embedding model is enforced (before, watch could mix vectors of another model into the index) and a failed rebuild is rolled back.
- `gleann graph report` prints the absolute path of the report and does not overwrite a `GRAPH_REPORT.md` that belongs to another index unless `--force` is given.

### Changed
- **Memory injection has a token budget.** The `<memory_context>` window is capped at 4000 estimated tokens by default (`GLEANN_MEMORY_MAX_TOKENS`, `0` = unlimited; manager setting `MaxContextTokens`). A typical memory set stays under the cap and renders unchanged; over budget, whole blocks are dropped lowest-priority first (short-term, then medium, then long-term; within a tier the older, then the less-accessed block), never truncated. `gleann memory context --json|--verbose`, REST `GET /api/blocks/context` and MCP `memory_context` `verbose` report the injected and dropped blocks with token estimates, and drops are logged.
- **Memory search is ranked.** Queries are tokenised (camelCase and snake_case aware) and scored with BM25 over label, content, tags, paths and symbols, so word order no longer matters; exact phrase matches still rank first and ties go to the newer block. `memory forget` (CLI, MCP, REST) still deletes only verbatim matches.
- `docs/evaluation.md` and `gleann bench --agent` state that the agent suite is a simulated scenario with assumed numbers, not a measurement.

### Added
- **A search does not wait behind a build in the in-process `eif` embedder.** Calls of up to 4 texts (a search query) run on a second model instance, loaded on first use under its own lock, instead of queueing behind a build's batch on the primary instance; if the second instance cannot be loaded they take the old path, and closing the embedder frees both. Instances share the memory-mapped model file and add only their activation scratch. Measured with multilingual-e5-small (q8_0) on linux/amd64, 16 cores: embedding one query while a build batch runs takes 12 ms instead of 3.7 s (`BenchmarkEIFQueryDuringBuild`; set `GLEANN_TEST_EIF_MODEL` to run it and the lane tests). Not yet measured on arm64 or macOS.
- **`X-Gleann-Cover` for multi-index pass-through answers.** When the best passages overall come from one or two indexes, an index whose best passage is close to the overall best (vector distance within a margin, or BM25 score at least a share of the best and above a floor) keeps that passage, replacing the lowest-ranked extra passages of other indexes; the top-k and `X-Gleann-Max-Context-Chars` limits hold, no index loses its only passage, and the other passages keep their order. Off by default (`proxy_cover`); thresholds `proxy_cover_margin`, `proxy_cover_share`, `proxy_cover_floor` or the `X-Gleann-Cover-Margin|Share|Floor` headers. The defaults (0.1, 0.6, 1.0) are starting points and are not calibrated to a particular embedding model.
- **Pass-through proxy context intro is configurable and asks for the question's language.** The sentence before the retrieved passages comes from `proxy_context_intro` (or `GLEANN_PROXY_CONTEXT_INTRO`; the default is the former English text) and gleann always appends "Answer in the language of the user's question.", so documents and questions in different languages get an answer in the asker's language without language detection.
- **`X-Gleann-Hybrid-Alpha` on the OpenAI-compatible proxy.** A number from 0 to 1 sets the vector/lexical weight of the retrieval for that request in both proxy modes; `0` searches lexically only (no query embedding), which keeps working for multi-index answers (the cross-index ranking uses the BM25 scores then). A value that is not a number in range is ignored, like `X-Gleann-Top-K` and `X-Gleann-Min-Score`.
- **`GET /api/storage` reports the whole data folder.** Besides the index directory it returns `data_dir` (the gleann home, `GLEANN_CONFIG_DIR` or `~/.gleann`), `data_bytes` and `data_folders` (bytes per top-level entry, so model downloads show up). Only regular files count, a symlinked home is resolved, and the walk is cached for 60 s so polling does not re-read large model folders. New `gleann.MeasureDir`.
- **HNSW vectors can be stored as float16** (`hnsw_config.vector_dtype: f16` or `GLEANN_HNSW_DTYPE=f16` for new builds; default `f32`, unchanged). Distances are computed from the half-precision values directly, without a float32 copy in memory. On 100K × 768 synthetic vectors: index file 315 → 169 MB, memory after load 868 → 514 MB (in-RAM searcher) and 328 → 182 MB (memory-mapped), recall@10 unchanged, search p50 +2 % (RAM) / +10 % (mmap); retrieval-quality gate Dense MRR 0.297 → 0.296. A float16 index is written as HNSW file version 2, which older gleann versions cannot read; float32 indexes keep version 1.
- **DiskANN maps its vectors instead of reading them into RAM; searcher caches can have a memory budget** (WP-2.7). `diskann_config.use_mmap` defaulted to true but was ignored; DiskANN (the default backend) now memory-maps the raw vectors and releases the mapping when the searcher closes. At 100K passages (format 2): first `serve` query 338 → 200 ms, `serve` RSS 191 → 148 MB, warm latency unchanged. One top-level `use_mmap` (`--no-mmap`, `GLEANN_MMAP`) overrides every backend; unset, the per-backend keys decide (both default to mapped). `searcher_cache_budget` / `GLEANN_SEARCHER_CACHE_BUDGET` (e.g. `2GB`, default 0 = count limit only) evicts least-recently-used searchers in `serve` and the MCP server until their index files fit.
- **Sleep-time reflection as diff and persistent cursor** (WP-4.4): sleep-time engine cursor resumes from SQLite `memory_meta`, reflection writes route through `RememberBlock` without overwriting or deleting original blocks, and `gleann memory reflect [--dry-run] [--revert <run-id>]` runs on demand, tests proposed changes, or reverts added blocks.
- **Markdown export and import for memory** (`gleann memory export --dir <dir>`, `gleann memory import --dir <dir>`): lossless, idempotent round trip for memory blocks and conversation digests with full YAML front matter and Windows-safe file names.
- **Retrieval quality gate in CI** (`internal/quality`): builds an index of a pinned snapshot of the repository (one archive, 320 files) with a deterministic embedder and fails when file-level MRR or R@10 of BM25, dense or hybrid search drops more than 0.01 below the stored baseline on 141 tasks. `go test ./internal/quality -run TestRetrievalQuality -update` rewrites the baseline on purpose.
- **Docs ↔ code check** (`internal/doccheck`): fails when a REST route, `GLEANN_*` variable, MCP tool or CLI command is missing from the docs, or documented but gone from the code.
- `allowed_roots` setting (settings screens, web UI, `config.json`, `GLEANN_ALLOWED_ROOTS`).
- [RFC 003](docs/plans/003-storage.md) (SQLite record store, persisted lexical index, code graph in SQL), [RFC 004](docs/plans/004-v1.20-sqlite-only.md) (one SQLite store, no Kùzu, no format 1), [RFC 005](docs/plans/005-incremental-vectors.md) (incremental vector updates) and the decision record [docs/decisions/kuzu-to-sqlite.md](docs/decisions/kuzu-to-sqlite.md).

### Added
- **Query expansion (`--expand`, HyDE).** Before searching, an LLM writes a short code snippet that would answer a natural-language question, in the index's dominant language, and the search uses the question plus the snippet. `search`/`ask --expand`, `--no-expand`, `--expand-model`; REST search and ask `"expand": true`; MCP `gleann_search` `expand`; settings `expand` and `expand_model`. On 121 questions about the gleann code base MRR rose from 0.485 to 0.629 and R@10 from 0.71 to 0.81 with qwen3.5:9b (~1.5–3 s per new query on a GPU). Off by default: a 3B model gained only 0.03.
- **Catalog reranker `ms-marco-minilm-l6`.** English cross-encoder, best for code: on English code questions MRR +0.07 (mMiniLMv2: +0.01). The published GGUF lacks the model's pooler layer, which makes its scores nearly constant; `gleann models download` adds it from the original checkpoint (~600 KB, HTTP range requests).
- **`gleann search --explain`.** Shows the most important segments of each result (~70 ms per result) and the BM25 weight of each query term.
- **MCP `gleann_search` `focus`.** Returns only the most relevant quarter of each result, ~4× fewer tokens.
- **`gleann ask --cite` and REST ask `"cite": true`.** Link each answer sentence to the context passage it came from and list the passages used (~100 ms, prompt unchanged).
- **Pass-through mode for the OpenAI-compatible proxy** (`proxy_mode: passthrough` setting or `GLEANN_PROXY_MODE`). The client's request goes to the LLM server unchanged except for the retrieved context, and the reply streams back byte for byte (reasoning, metrics, extra fields); `POST /stop` is forwarded. - **`GET /api/storage`** (admin): disk space of every index, index and passage counts, and the free space of the file system.
- Makefile: `ARM64_CFLAGS` for the arm64 eif cross build (e.g. `-march=armv8.2-a+dotprod+fp16`).
- `gleann bench`: `GLEANN_BENCH_PERTASK` writes per-task rows; `GLEANN_BENCH_RERANK=1` and `GLEANN_BENCH_EXPAND_MODEL` add reranker and HyDE strategies.
- [docs/retrieval-experiments.md](docs/retrieval-experiments.md): what was measured, what was shipped and what was left out, including the CPU cost of reranking.

### Changed
- **Built-in reranker defaults.** With no `rerank_model` set, results that are mostly source code are reranked with `ms-marco-minilm-l6` when it is downloaded (mMiniLMv2 otherwise and for documents), and the built-in engine scores 20 candidates of 500 characters instead of every candidate in full (~2.5× cheaper on a CPU, no loss on the benchmark). `--rerank-pool` and a configured model still win; server rerankers are unchanged.
- Catalog ids work as reranker models (`--rerank-model ms-marco-minilm-l6`), also when the engine is chosen automatically.
- **Identifier queries are not reranked.** One-word or code-shaped queries (`LeannSearcher`, `parse_args`, `func NewServer`) keep the first-stage order: passage rerankers demote exact symbol hits (symbol-query MRR −0.05 without this).
- `--rerank-pool` limits only the candidates sent to the reranker; the first stage keeps its wide lists (narrowing them lowered quality).
- **`rerank_provider: ollama` returns an error.** Ollama has no rerank API; the old fallback compared embeddings, scored worse than no reranking and crashed for bge-reranker-v2-m3. Use `eif` or `llamacpp` with a llama-server `--reranking` (which now uses `/v1/rerank`).

### Fixed
- **E5 embedding models get their `passage: ` / `query: ` prefixes.** The prompt template settings were never used, so `multilingual-e5-small` (the Turkish-capable default) embedded text without the prefixes it is trained with and ranked relevant passages low. New indexes record the prefixes in their meta and every search, update, `--explain` and `--cite` uses them; existing indexes keep working unchanged (rebuild one to get the prefixes).
- **Results of several indexes are ranked by their raw relevance.** Each index normalises its own best passage to about 1, so merged multi-index results put every document's best guesses on top and could crowd out the passage that answers the question. The proxy, `MultiSearcher` and `SearchMultiple` now fuse the raw vector distances and BM25 scores; reranked results keep their cross-encoder scores.
- Index-building uploads (`POST /api/indexes/{name}/upload`, `index-path`, `update`) get the build timeout (`GLEANN_TIMEOUT_BUILD_S`, 10 min) instead of failing with 504 after 60 s.
- `gleann ask --rerank` and `gleann ask --graph` had no effect unless saved in the settings, and multi-index or `<name>-code`/`<name>-docs` asks and multi-index `search --rerank` never reranked.
- `gleann ask` put the values of `--rerank-url`, `--rerank-pool` and `--rerank-provider` into the question.
- REST `ask` searched a second time to report sources, which could differ from the passages the answer was based on.
- `gleann bench` used the configured embedding model instead of the index's; a mismatch silently turned every strategy into BM25.
