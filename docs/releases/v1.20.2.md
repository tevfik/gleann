# gleann v1.20.2

A performance, correctness and contract release. Index builds are about twice
as fast (HNSW) and 3.7× as fast (DiskANN) with the same or better recall,
filtered search is exact where it used to be approximate, `gleann index sync`
resolves Go calls with `go/types` exactly as a full build does, long-term
memories no longer expire, sibling repositories' memories no longer leak into
`ask`/chat prompts, and the OpenAPI spec now covers every REST route so
Swagger UI and Postman import see the whole API. It also closes three security
holes (an A2A query token that could write memory and read local files, a Go
module load that could reach the network, and an installer that did not verify
its download) and makes `index remove`, `graph build` and `graph hook
uninstall` safe against destroying data they do not own.

**The index format is unchanged and nothing has to be rebuilt.** Existing
indexes keep their stored backend and settings. One default changes for new
indexes: **HNSW is now the default pure-Go vector backend**, replacing
DiskANN, across the CLI, REST builds and TUI onboarding/settings. Indexes
built on a machine whose installed `go` was older than the module's `go` line
may have a syntactic-only code graph; `gleann graph build <name>` refreshes it
(see Code graph).

## Security

- **A2A: a query token could write memory and have local files read.**
  Through `POST /a2a/v1/message:send`, a token of scope `query` could store
  memory blocks (which are later injected into agents' prompts) and have the
  `multimodal-analyze` skill read a file of the server by path. Both now need
  an admin token; a query token can still search and recall memory and
  analyze files it attaches. With authentication off (loopback only) nothing
  changes.
- **The exact Go load of the code graph could reach the network.** gleann
  runs `go list` with `GOPROXY=off`, but with `go.sum` entries present a
  module path matched by `GOPRIVATE` or `GONOPROXY` took the direct route (a
  fetch attempt was observed). The load now also sets `GOPRIVATE=`,
  `GONOPROXY=none` and `GONOSUMDB=*`. The user's `GOFLAGS` are kept except
  `-mod`, and a vendored module loads with `-mod=vendor` instead of failing.
- **`scripts/install.sh` verifies the download.** The archive is checked
  against the release's `SHA256SUMS`; a missing sums file, a missing entry or
  a mismatch stops the installation. `GLEANN_SKIP_CHECKSUM=1` skips the check.
- **The OpenAPI spec declares its authentication.** `bearerAuth` (HTTP
  bearer) is declared once at the top level of `/api/openapi.json`, so a
  Postman import surfaces a single scheme every operation inherits; the four
  public routes (`GET /health`, `GET /.well-known/agent-card.json`,
  `GET /api/docs`, `GET /api/openapi.json`) override it with an empty list.

## Storage, vector backends & sync

- **HNSW is the default pure-Go backend.** New pure-Go indexes default to
  HNSW across CLI, REST (`POST /api/indexes/{name}/build` validates explicit
  `backend` values) and TUI onboarding/settings. Existing indexes keep their
  stored `meta.Backend`, including legacy `diskann_config.use_mmap=false` RAM
  search for DiskANN indexes.
- **HNSW builds about twice as fast, same index.** The node table is a dense
  slice with a map for sparse IDs, the visited set and search buffers are
  reused instead of allocated per insert (130 allocations per insert became
  5), each link keeps the distance it was made with, and distances to several
  neighbours are measured at once (four independent accumulations, each
  summed in the same order as before). `idx.index` and every search result
  are bit-identical to the previous build, checked by checksum for L2, cosine
  and inner product and by a reference implementation of the old algorithm
  kept in the tests. Vector build of 20,000 × 384: 15.6 s → 7.5 s;
  5,000 × 768: 6.45 s → 3.21 s. With a lookup embedder (20,000 passages of
  384 dimensions, 4 CPUs) the whole build went from 44.6 s to 32.4 s, helped
  by lexical staging that commits once instead of once per source file
  (`bench/vectordb/cmd/buildbench` is the harness).
- **DiskANN builds: 3.7× faster, higher recall.** Nodes keep up to 1.3 × R
  neighbours during the build and are pruned to R once at the end (the degree
  slack of the Vamana paper). 100K × 768, 4 CPUs: build 6,489 s → 1,773 s,
  recall@10 0.878 / 0.965 / 0.989 → 0.920 / 0.981 / 0.994 at search L
  64 / 128 / 256. A best-first beam for the build search was tried and
  rejected: faster (782 s) but recall 0.512 at L 64, so the build keeps its
  insertion-order walk. The loss is invisible at 10K vectors and on real
  384-dimension embeddings, so `bench/vectordb/gate` now holds DiskANN to
  0.98 recall at 10K.
- **DiskANN PQ training runs in parallel.** The sub-quantizers' Lloyd
  iterations run on all CPUs; starting centroids are still drawn in order
  from one generator, so the codebook is bit-identical. PQ training was 46%
  of a 5,000-vector build.
- **DiskANN `search_l` scales with the index when unset.** Zero (the default)
  now means 100 up to 25,000 vectors and 100 × sqrt(n / 25,000) above, capped
  at 512; a set value is used as given. 100K × 768: auto L = 200, recall@10
  0.991 at 9.5 ms p50 (L 256 fixed: 0.994).
- **Filtered search on DiskANN is exact for selective filters.** The DiskANN
  searcher did not implement `VectorDistances`, so selective filters fell
  back to the approximate widen loop. It now scores SQL-pre-selected matches
  from the raw stored vectors (never PQ) on both RAM and memory-mapped load
  paths. `bench/vectordb/cmd/filtbench`, 1,000 queries, recall@10 and p50,
  same index before → after:

  | | before | after |
  |---|---:|---:|
  | 100K × 384, 1% selectivity | 0.824 (123 ms) | 1.000 (72 ms) |
  | 100K × 384, 10% | 0.982 (11 ms) | 0.9996 (110 ms) |
  | 10K × 384, 1% | 0.901 (102 ms) | 1.000 (10 ms) |
  | 10K × 384, 10% | 0.843 (7 ms) | 0.9996 (13 ms) |

  The 10% rows pay a full-table scan over the filter field, as on HNSW; 50%
  and unfiltered searches are unchanged. The recall gate gained a
  `gleann-search-diskann` row.
- **Small filters are scored exactly on any backend that can score explicit
  IDs.** The widen-until-k loop stopped as soon as k candidates passed the
  filter, but those came from an approximate search over a widened pool. On a
  format-2 index whose backend can score explicit IDs (HNSW and DiskANN with
  stored vectors), a filter estimated to match at most 12,000 passages and at
  most a fifth of the index is now answered by scoring all its matches
  exactly (SQL pre-selection, then vector distances). If the estimate was off
  or the vectors are pruned, the loop widens as before. The pre-selection
  evaluates the filter on every row (about 60 ms at 100K passages), so this
  applies to indexes of up to 200,000 passages; larger ones keep the loop's
  result. 100K × 768, default HNSW, 1,000 queries: 1% selectivity
  0.862 → 1.000 (165 → 74 ms), 10% 0.930 → 0.996 (17 → 112 ms), 50% 0.989
  either way; at 10K × 384 all rows reach ≥ 0.997.
- **Faster lexical staging, Go AST extraction and ignore-pattern matching,
  bit-for-bit identical indexes.** `Analyzer.TokenString` writes lowercased
  ASCII tokens directly into a preallocated buffer, passage storage extracts
  `source` without marshaling discarded metadata, Go graph extraction parses
  each file once with `parser.SkipObjectResolution`, and `pkg/walker`
  precompiles ignore patterns into exact/prefix/suffix/glob kinds. Measured
  via `bench/vectordb/cmd/corpusbench` with identical SHA-256 hashes across
  all 14 SQLite tables: corpus with graph 9.70 s → 7.49 s (−22.8%), without
  graph 20.31 s → 13.00 s (−36.0%); an independent 13,896-passage Go tree
  3.90 s → 2.12 s with allocations 856 MB → 407 MB.
- **Rollback-protected incremental sync, publication crash recovery and
  vector readability checks (`S6-row6`).** Missing or damaged store and
  `.index` faults are classified cleanly to trigger rollback-protected
  rebuilds without destroying intact indexes on empty-corpus failures or
  transient embedder outages. `updateIncremental` is guarded against
  non-regular or unreadable `.index` files; unreadable or directory `.index`
  files are reported in `CheckIndexHealth`, `gleann doctor` and `gleann index
  repair`; `has_graph` metadata is preserved across up-to-date syncs.
  `docs/cookbook.md`, `docs/graph.md` and `docs/troubleshooting.md` align.
- **`gleann index remove` no longer deletes any directory named like the
  index.** `gleann index remove src --index-dir .` removed `./src`, and so
  did `DELETE /api/indexes/{name}` for a directory of that name under the
  index directory. The directory is now removed only when it is empty or
  holds an index: every entry must be a file gleann writes and at least one
  must be an index file; otherwise the command fails and names the entry it
  found. Lock files, backups and an old `_graph` directory next to it are
  still cleaned.
- **`gleann index build` no longer starts on a home directory or a file
  system root by accident.** `--docs .` typed in the wrong directory read
  every file below it (hours on a large home). The build now stops before any
  work and says so; `--yes` indexes the directory anyway.
- **`--dry-run` and the `--max-minutes` gate count the files a build actually
  reads.** The pre-flight estimate walked the directory on its own and
  skipped only hidden directories, so `node_modules`, build outputs and
  everything in `.gitignore` / `.gleannignore` were counted (this repository:
  11,376 files / 1.5 GB estimated, 1,469 files / 73 MB indexed). It now uses
  the walk of the build (`gleann.EstimateJobWalk`).
- **HNSW: inserting into an imported graph crashed, and `Size()` counted a
  re-inserted ID twice.** `NewGraphFromTopology` left the random source and
  the metric name unset, so the first `Insert` hit a nil pointer and float16
  vectors of a cosine or inner-product graph were compared with L2.
- **`docs/configuration.md` listed DiskANN keys that do not exist**
  (`pq_train_size`, `l_search`). The section now shows the real keys, and a
  doc test compares it with the config struct.

## Code graph

- **`gleann index sync` resolves Go calls with `go/types`, as a full build
  does.** A sync used the syntactic resolver, so a synced file lost its
  method calls and interface edges until the next full build. A sync now
  loads the packages of the changed files, and the packages that declare the
  interfaces their types implement, and stores the same symbols and edges as
  a full build of the same tree (on this repository: equal checksums over all
  11,850 symbols and 47,365 edges after an edit, and again after a second
  one). A file synced while its package did not type-check is resolved again
  by the next syncs until it does. Cost: the graph step of a one-file sync
  goes from about 0.13 s to 0.34–1.16 s. Without a `go` toolchain, or when the
  load fails, the sync warns and stays syntactic; `GLEANN_GRAPH_EXACT=0`
  turns exact resolution off. One limit: a new type that implements an
  interface of a package it does not import gets that IMPLEMENTS edge at the
  next full build or `gleann graph build`.
- **Exact resolution covers `_test.go` files.** `LoadExact` and `LoadExactDirs`
  type-check each package's test files (`Tests: true`), resolving calls from
  internal and external tests (recovering 2,226+ caller edges on gleann
  itself, test-only recall 0.745 → 0.998). Broken test files are kept and
  retried cleanly during incremental sync without disturbing production
  edges; synthetic test runners are excluded without dropping standalone
  `*.test` `main` packages or modules.
- **Exact resolution covers cgo files.** `go/packages` reports their generated
  copies in the build cache, so they fell back to the syntactic resolver and
  the package prefix came from a cache path. They are mapped back to their
  source files, in full builds too.
- **Nested `go.mod` submodules and `go.work` workspaces resolve calls.**
  `DiscoverModules` loads each nested `go.mod` from its own module root with
  its real module path, keeps `go.work` scoped to workspaces named via
  `golang.org/x/mod/modfile.ParseWork` (nearest/deepest element-boundary
  tie-breaking), isolates unlisted submodules with `GOWORK=off`, skips
  ignored `_`/`.` Go fixtures, and reports moduleless `.go` trees cleanly on
  stderr. `golang.org/x/mod` is a direct dependency now.
- **The exact resolver no longer fails silently on an older installed `go`.**
  gleann ran `go list` with `GOTOOLCHAIN=local`: on a machine whose `go` is
  1.22 and whose `go.mod` asks for 1.25, the load failed and the build fell
  back to the syntactic resolver without a word, so `gleann graph explain
  <method>` showed no callers. gleann no longer overrides `GOTOOLCHAIN`
  (downloads stay off: `GOPROXY=off`), and a build whose exact resolution
  fails prints a warning with the reason. On this repository with `go`
  1.22.2 installed: methods with at least one caller 0 of 1,867 before,
  1,093 after. Indexes built on such a machine need `gleann graph build
  <name>`.
- **`TestCallers` across MCP, REST and CLI.** Calling test functions are
  separated cleanly into `TestCallers` / non-nil `test_callers` JSON arrays
  alongside production `Callers` in MCP `gleann_impact` and REST graph
  `impact` (including refreshed `sqlite_lite` REST impact goldens), and
  `gleann graph explain` renders a capped, column-aligned `Test Callers`
  section.
- **Tree-sitter extraction for six more languages: Kotlin, Lua, Scala,
  Svelte, Ruby and Elixir.** Declaration and call edge extraction is complete
  across chunker and graph indexers. Parenthesized/negated/nested Elixir
  `when` guard expressions, module attribute names and
  `@spec`/`@type`/`@callback` typespecs no longer produce phantom `CALLS`,
  while real compile-time attribute calls, qualified keyword calls and
  parenless `|>` pipe targets are preserved. `docs/treesitter.md` and
  `docs/graph.md` align.
- **Lite builds surface a non-Go symbol notice on every query surface.** CLI
  (`explain`, `callers`, `deps`, `path`, `query`), MCP
  (`gleann_graph_neighbors`, `gleann_impact`), REST (`POST
  /api/graph/{name}/query`) and A2A surface the `without tree-sitter` notice
  accurately when non-Go symbols are queried from a lite build. `graphstore`
  applies prefix/exact/set meta mutations deterministically before
  recomputing `graph_treesitter` inside the same transaction, so subsequent
  Go-only syncs preserve the markers.
- **`gleann graph build` keeps the document graph and takes the index lock.**
  A graph build on its own replaced the document nodes with an empty list, so
  `graph toc` listed nothing afterwards, and it could run while a build or
  sync of the same index was writing. It now takes the index lock and reads
  the documents of the source directory, as `index migrate` does (plugin
  extractors included, so it takes longer on a tree with many documents);
  when it finds no documents, the stored document graph is left as it is.
  `POST /api/graph/{name}/index` behaves the same.
- **`gleann graph hook uninstall` no longer deletes the user's own
  post-commit hook.** gleann's section is now between `# BEGIN GLEANN HOOK`
  and `# END GLEANN HOOK` and only that is removed (a section written by an
  older version is recognised too); the file is deleted only when nothing
  else is left. The hooks directory comes from `git rev-parse --git-path
  hooks`, so worktrees, subdirectories and `core.hooksPath` work, and the
  hook runs `index sync` instead of a full build.
- **Renaming a Go file within its package no longer loses its symbols on the
  next sync.** The new file's declarations were matched against the old
  file's rows and then removed with them, so the file stayed dirty and its
  callers unresolved until a full rebuild. Deleted files are now retracted
  before changed files are applied.
- **A sync no longer adds README, LICENSE and `go.mod` to the code graph** as
  `block_N` symbols, and the first sync with this version removes the rows an
  older gleann stored.
- **The graph test suite runs on Windows.** The OS-independent test files
  that were excluded from Windows while the graph store was a CGo dependency
  build and run there now, and a guard test rejects any test file in the
  package that excludes Windows again.

## Agent memory

- **Long-term memories no longer expire or decay by age.** `ValidityScore()`
  applied a 90-day half-life decay to every tier, so unconfirmed `long` facts
  dropped below the injection cutoff after ~119 days and were purged by
  `gleann memory compact`, and `IsStale()` flagged `long` blocks after 180
  days. `TierLong` is now exempt from age decay and age staleness while
  staying mutable via edits, duplicate merges, explicit deletion, suspect
  marking, caller-set `expires_at`, and Bayesian conflicts. RFC 009 (draft,
  `docs/plans/009-memory-tier-lifetime.md`) specifies the rest of the tier
  lifetime policy: three-source TTL precedence (per-fact explicit expiry,
  user setting, fixed default) for short/medium memory, `EndSession`
  promotion rules, long-tier permanence, and `compact --dry-run`. The
  long-tier exemption is implemented; the lifetime policy is not yet.
- **`gleann ask`, chat and the TUI no longer inject sibling repositories'
  memories.** `DetectRepoScope`/`NormalizeGitRemote` live in
  `pkg/memory/scope.go`, and `InjectRepoContext` is wired into `cmdAsk`,
  `chat.go` and `agentchat.go`, matching MCP's repository scope while keeping
  global blocks and ancestor scopes visible.
- **Sleep-time reflection no longer loses conversations, clobbers edits or
  reverses confirmations imperfectly.** Mid-cycle conversation updates, retry
  exhaustion bounds and same-scope overwrite preservation are handled safely
  without losing entries behind `lastRun`; `RevertReflection` unwinds multiple
  confirmations of the same block in LIFO order while preserving subsequent
  external edits; CLI/MCP memory inspections format block contradiction
  notices safely when metadata is nil.
- **Deterministic contradiction detection: fewer false positives, standard
  Turkish imperatives handled.** `ContradictionCheck` requires matching
  non-empty residuals, recognizes quoted polarity tokens and signed negative
  numbers (`-5` vs `5`), folds Turkish diacritics with rune-length bounds
  (`aç/açma`, `seç/seçme`, `çık/çıkma`, `gör/görme`, `kapıyı`, `dosyayı`),
  uses Turkish vowel harmony and a closed short-verb lexicon plus English
  pronoun/article guards (`I hired Al`/`Alma`, `AC`/`ACME`, `dog`/`dogma`),
  and preserves 2-letter Turkish imperative roots (`at/it/in/as`) without
  breaking English stop-word filtering.
- **The recall graph matches entities and relation types case-insensitively
  across Unicode.** Searches and relation-type filters use one Go
  case-folding path, so `istanbul` finds `İstanbul` and `DIYARBAKIR` finds
  `Diyarbakır`; backfilled seed entities expand to their relations within the
  node cap, and relation-type deduplication folds case the same way. The
  recall-graph REST documentation in `docs/api.md` matches the behaviour.
- **Entity injection batches vector updates once per request, last-wins.**
  `EntityService` dispatches non-empty batch updates through
  `gleann.VectorBatchSyncer` / `LeannSyncer.AddContents` instead of rebuilding
  the HNSW vector index per entity (1,000 entities → 1 publication), and
  deduplicates repeated entity IDs last-wins before filtering empty content
  in both `EntityService` and `LeannSyncer.AddContents`, so cleared duplicates
  never publish stale text. `docs/memory_engine.md` and
  `docs/plans/005-incremental-vectors.md` align.
- **The retired memory roadmap is archived.** `docs/ROADMAP-agent-memory.md`
  described a removed design; it now lives in `docs/releases/` behind a
  historical banner, and a doc test rejects the removed mechanisms' terms in
  the active docs and the README outside explicitly historical sections.

## REST, OpenAPI & Postman, MCP, CLI & plugins

- **Read-only passage and section listings (RFC 004 G8).** `GET
  /api/indexes/{name}/passages` and `GET /api/indexes/{name}/sections` serve
  bounded read-only pages straight from SQLite (`ORDER BY id LIMIT/OFFSET`,
  default 100, max 1000) without loading vectors or the embedder. Sections
  are grouped from passage metadata (`section_id`, `section_title`,
  `section_path`, `section_summary`, falling back to `heading`/`title`).
  Query token scope plus `X-Gleann-Target`/`GLEANN_TAGS` access isolation is
  enforced; a missing index answers 404 without creating `.db` files, and a
  format-1 index answers 409 with the migration hint. `docs/api.md` and the
  OpenAPI spec are updated.
- **100% OpenAPI 3.0 route parity.** Every REST route the server registers
  now appears in the spec at `GET /api/openapi.json` — including the config
  and settings registry, the plugin catalog and plugin runtime, the model
  catalog and downloads, system and proxy control, conversations (update
  title, clear all), index metadata `PATCH`, and `POST /api/blocks/compact`
  — and the spec promises no route the server does not answer.
  `TestOpenAPIMatchesRegisteredRoutes` in `internal/doccheck` fails the build
  when the router and the spec drift apart, and `TestOpenAPISpecValidJSON`
  keeps the document valid. The spec is ready for Swagger UI (`GET /api/docs`)
  and Postman import: **File → Import →
  `http://localhost:8080/api/openapi.json`**, then set the collection's
  authorization to **Bearer Token** with a token from `gleann token create`
  (see `docs/api.md`).
- **MCP server instructions, tool annotations and the `MCP-06` contract
  suite (`5.2a`).** Profile-aware `WithInstructions` guidance covers every
  enabled tool (including custom `--tools` subsets and `gleann` vs `grep`
  routing). All 37 tools carry explicit read-only / destructive / idempotent
  / open-world annotations (15 open-world: the 8 embedder/LLM tools and 7
  REST-forwarding memory/session tools; 22 local-only). The core profile's
  tool count aligns (11 tools in `gleann mcp --help` and `docs/mcp.md`), and
  loopback contract tests verify both `/api/embed` and remote `/api/blocks*`
  REST egress alongside local-only controls.
- **`gleann_gain` reports real accounting.** Nothing wrote to the counter the
  MCP tool reads, so it always answered zero. Every successful `gleann_shell`
  and `gleann_read` call now adds the estimated tokens of the raw input (the
  command output, or the whole file) and of what was returned (about four
  characters per token). The counter belongs to one MCP server process and
  starts at zero with it; the tool description and the docs no longer say
  "across sessions".
- **CLI `--quiet` suppresses consistently.** `--quiet` silences the
  multi-index `--explain` note, `index sync` status stdout and default
  progress, and the embedded `llama-server` startup and shutdown messages
  (`search`, `ask`, `chat`, `serve`, `index build`, `index sync`, `index
  watch`) while keeping real errors on stderr; `hasFlag` uses last-wins
  across mixed boolean spellings. `gleann index build --help` now lists
  `--quiet` with these semantics, `gleann search --help` lists every flag the
  command accepts (checked by a test against the flag table), and
  `docs/configuration.md`, `docs/api.md` and `docs/env-vars.md` align
  supported provider lists with the `-tags eif` and `-tags native` caveats.
- **Saved onboarding settings reach the loaded configuration.**
  `A2AEnabled` and `LlamaCPPConfig` were persisted but never mapped; they are
  now, and a test fails when a persisted onboarding field is neither mapped
  nor allowlisted with a reason.
- **Plugin shutdown sends a shared `SIGINT` grace period before killing
  children.** `PluginManager.Close()` and `stopPluginLocked()` share one
  graceful stop path (10 s default, configurable via
  `GLEANN_PLUGIN_STOP_GRACE`) across all active plugins in parallel, and fall
  back to immediate `Kill()` when interrupt delivery is unsupported (such as
  Windows). Documented in `docs/env-vars.md`.
- **Plugin registry versions are dynamic.** Stale hardcoded `"version":
  "1.0.0"` fields for `gleann-plugin-docs` and `gleann-plugin-sound` are gone
  from `plugins-registry.json` (installed/latest versions resolve from
  release tags), the sound plugin icon aligns with `defaultCatalog` (🎙️),
  and `TestCatalogRegistryParity` verifies full field parity and rejects
  placeholder versions.

## Benchmarks, build & CI

- **`bench/vectordb` runs on real embeddings.** `cmd/exportvecs` writes the
  stored vectors of a gleann HNSW index to a `.fvecs` file, and `vectorbench
  -vectors <file>` / `filtbench -vectors <file>` run on them (queries are
  held out of the file). `cmd/buildbench` times a build through
  `gleann.NewBuilder` for `-backend hnsw` or `diskann`; `filtbench -backend
  diskann` measures the real search path of either backend.
  `bench/vectordb/gleannsearch` is the shared build-and-query helper.
- **Paired comparisons: `gleann benchmark --compare <A>,<B>`** (in-run or
  standalone `<fileA>[:<Strategy>],<fileB>[:<Strategy>]`) computes paired
  bootstrap confidence intervals and exact sign tests across strategies,
  with explicit per-metric presence tracking so omitted JSONL fields never
  zero-fill. It documents and logs the `bench/tasks/gleann.json` fallback,
  validates `--per-task` creation and write errors, and removes the
  process-global `GLEANN_BENCH_PERTASK` env mutation. An offline `--compare`
  accepts strategy names that contain commas and paths that contain
  parentheses.
- **An honest Ripgrep baseline.** `gleann benchmark` invokes `rg -F -c -i`
  with `--no-ignore-parent` and `--no-require-git` to match `pkg/walker`
  across git and non-git parents, retries without those compatibility flags
  on `rg < 12` unknown-flag exit code 2 without swallowing genuine failures,
  measures retrieved file tokens accurately, and marks missing, moved or
  non-directory corpora as unavailable cleanly without `<nil>` strings.
- **Honest benchmark reports.** The tasks file is no longer counted as a
  result when it is part of the index (it held every query verbatim and took
  the first ranks; its hits are dropped, with a note). The vector row is
  labelled with the backend of the index searched, not the configured
  default. The report no longer claims "N x Higher Recall" whatever the
  numbers: it names the best strategy of each metric (also when that is
  BM25), says when GraphRAG and Hybrid are identical, and states the weight
  of one task. Hybrid rows are labelled with the alpha that ran (`Hybrid
  (default, α=<alpha>)`); `NaN` or infinite weights fall back to 0.7 instead
  of silently degrading retrieval.
- **Docker images build again.** `Dockerfile` and `Dockerfile.full` used Go
  1.24 while `go.mod` needs 1.25.9; both now use `golang:1.25.9` and build
  for the target architecture.
- **`make full` builds in Docker without a host Rust toolchain and on
  macOS.** The build mode is chosen when the Makefile is parsed, the Docker
  recipe builds `libbitllm.a` and links with `$ORIGIN` run paths, the Darwin
  branch uses `libfaiss.dylib`, `-lomp` and `install_name_tool`, and `make -n
  full` no longer deletes `internal/server/dist`. A test checks the
  prerequisites for each toolchain combination.
- **`scripts/build-faiss.sh`** builds FAISS (static, with the C API) into
  `deps/faiss_install` for `make full`. `deps/` is no longer tracked in git
  (a prebuilt FAISS for one platform, 16 MB); `chromem-go` is no longer a

  least-privilege `permissions`.

  body).
