# gleann v1.21.1

A patch release for v1.21.0. It closes a race between server builds and CLI
builds, makes index metadata updates safe across processes, protects the
server's path and auth settings from the config API, validates metadata
filters on REST and MCP instead of ignoring bad ones, and removes the admin
token from the `gleann serve` banner. It also fixes several CLI and
`gleann install` defects found while testing v1.21.0. There is no schema
change and no index needs a rebuild.

**Upgrade notes / behaviour changes.** Read these before upgrading.

- **REST filters are strict.** `POST /api/search` and multi-search answer 400
  for a `metadata_filters` item with an unknown key, no field, or a missing or
  unknown operator. The key is `operator`: the OpenAPI spec said `op`, which
  the server ignored, so such filters matched nothing. MCP returns a tool
  error for a malformed `filters` entry.
- **The config API cannot change protected keys.** `POST /api/config` and
  `PUT /api/settings` answer 403 when a body changes `allowed_roots`,
  `index_dir`, `auth` or `cors_origins` (a value sent back unchanged is
  accepted). Edit `config.json` or use `gleann setup`, then restart. A
  settings body with trailing data is a 400.
- **`setup --bootstrap` needs `--force` to replace a completed config.** The
  old file is kept as `config.json.bak` (mode 0600).
- **Ollama rerank is no longer enabled** by bootstrap or auto-setup, because
  Ollama has no rerank API. `gleann doctor` warns when `rerank_enabled` is set
  with a provider that cannot rerank.
- **Bad CLI input exits 2.** An empty `search` query and a numeric flag with a
  value that is not a number (`--top-k 10x`, `--hybrid abc`) exit with status
  2. `--hybrid abc` used to set the weight to 0.
- **`gleann serve` no longer prints the admin token.** Use `gleann token
  show`.
- **Re-run `gleann install` to get hook v2.** The SessionStart hook now runs
  `gleann memory context --max-bytes N`; v1 hooks are recognised and replaced.
- **`memory --scope repo` means the detected repository** (also `.`) for
  `remember`, `context`, `failure` and `list`. It used to store the literal
  `repo`. `memory list` shows each block's scope.
- **A build while another process holds the index lock returns 409.**
  `POST /api/indexes/{name}/build` takes the same `<name>.lock` as CLI build
  and sync.
- **Metadata updates wait up to 5 s for another process.** They take
  `<name>.meta.lock`; a longer wait ends in an error instead of a lost write.
- **A model mismatch returns 409**, not 500, on search, ask and index reads.

## Security

- **The config API cannot widen the path policy.** An admin token could change
  `allowed_roots`, `index_dir`, `auth` and `cors_origins` through
  `POST /api/config` and `PUT /api/settings`; both now refuse (403).
  `PUT /api/settings` rejects a body that is not exactly one JSON value, which
  used to bypass the protected-key check.
- **The admin token is not printed by `gleann serve`.** The banner names the
  token file, `gleann token show` and the `?token=` URL form without the
  value (logs, journald and screen shares kept it).
- **The REST HyDE expander cache is keyed by a hash of the API key**, so a
  rotated key takes effect instead of the old credential.
- **MCP filters are validated like REST.** `gleann_search`, ask and the
  progressive search used to skip a malformed `filters` entry, which widened
  the search; they now return a tool error.

## Fixes

- **Concurrent builds of one index through the server.** Two requests for one
  name run one after the other (one used to fail with `assigning slots`); a
  server build and a CLI build no longer overlap. Under `GLEANN_TAGS` the
  access check of a create is repeated under the lock, so two creates of one
  name cannot both pass it. The lock refuses an empty index directory.
- **Metadata updates across processes.** A CLI rebuild and a PATCH on a
  running server no longer overwrite each other. A missing index leaves no
  lock file.
- **Watch toggle.** It answers 503 when the metadata was not written (it
  answered 200), and `auto_watch` and `source_dir` are merged as a pair, so a
  rebuild cannot keep one and reset the other. Other metadata write failures
  are logged.
- **`gleann install`** writes `settings.json` and `opencode.json` in the
  user's key order without HTML escaping, and its SessionStart hook cuts on a
  character boundary. The post-commit hook's background sync prints nothing.
  Uninstall removes a `CLAUDE.md`, `AGENTS.md` or `GEMINI.md` that is
  whitespace-only afterwards and edits through symlinks instead of deleting
  them.
- **`setup --bootstrap`** honours `--model`, `--provider`, `--llm-model` and
  `--llm-provider`, which were ignored. `setup --force` keeps an existing
  `config.json.bak` and writes a timestamped one (mode 0600).

## Known limitations

- **`memory list` default scope.** `memory list` still lists blocks of every
  scope by default; the planned default of global plus the detected repository
  (with `--scope all`) is scheduled for v1.22.
- **Server-side watch does nothing.** The watch route and `auto_watch` report
  progress but no sync runs; planned for v1.22.
- **No CLI metadata-filter flag.** Filters are available on REST and MCP only;
  planned for v1.22.
- **First run without Ollama** has no embedded-model path yet; planned for
  v1.22.
- **RFC 008 (one retrieval service)** continues in v1.22 with the golden tests
  and the first implementation steps; the later steps are in v1.23 or later.
- **Windows is tested through CI only.** The file-locking changes in this
  release have not been run by hand on Windows.
