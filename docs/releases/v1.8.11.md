# gleann v1.8.11

The REST server now requires a token and listens on loopback by default. New
indexes keep their vectors, and you can switch an index between the two storage
modes from the CLI or the Index Manager. Several ways of losing an index or a
graph during sync are closed.

## Breaking changes

- **`gleann serve` needs a token.** Every route except `/health`, the A2A agent card,
  `/api/docs`, `/api/openapi.json` and the web UI's static files requires
  `Authorization: Bearer <token>`. Clients that send a dummy key (`api_key="none"`)
  get `401`. The first `serve` creates `~/.gleann/auth/admin.token` and prints a UI
  link with `?token=`; the local CLI and the stdio MCP server read the token
  themselves. `gleann token create|list|revoke|rotate|show` manages more tokens
  (scopes `query` and `admin`). `GLEANN_API_TOKEN` (16+ characters) sets a fixed token.
- **Loopback by default.** The default address is `127.0.0.1:8081` and `--port N`
  binds `127.0.0.1:N`. To expose the server use `--addr 0.0.0.0:N`; `auth: off`
  (`GLEANN_AUTH=off`) is refused on a non-loopback address. The Docker images now run
  `serve --addr 0.0.0.0:8080`. The token is printed in the container log; set
  `GLEANN_API_TOKEN` or mount `~/.gleann/auth` to keep it across restarts.
- **No CORS by default.** The wildcard `Access-Control-Allow-Origin: *` is gone. Allow
  origins with `cors_origins` or `GLEANN_CORS_ORIGINS`. On a loopback bind a request
  with a foreign `Host` gets `403` (DNS rebinding); extra names go in
  `GLEANN_ALLOWED_HOSTS`.
- **Uploads into a non-empty index return `409`** instead of replacing the index.
- **Vectors are stored by default.** HNSW no longer prunes embeddings on build, so a
  search embeds only the query instead of re-embedding about a thousand passages
  (6004 passages: 9.7 s down to 0.26 s). Indexes grow by about passages x dimensions x 4
  bytes. Existing recompute indexes are left alone.
- **`gleann index watch` syncs an existing index at start** instead of deleting and
  rebuilding it.

## Highlights

- **Storage modes.** `gleann index storage` lists every index with its mode and size;
  `gleann index storage <name> --set store|recompute` converts in place, using the
  embedding cache and restoring the index if it fails (6004 passages: 6 s). `--storage`
  and `storage_mode` set the choice for new builds. In the TUI Index Manager each
  index shows its mode, `s` switches it and `g` sets the default for new indexes.
- **Recompute search is batched** per graph hop (3k passages: 13.0 s down to 6.1 s) and
  an embedding failure during search is now an error instead of a silently degraded result.
- **Sync no longer destroys an index.** If the embedder fails during a sync that falls
  back to a full rebuild, the previous index is restored; `source_dir`, tags and
  description survive a rebuild. A sync in code mode no longer deletes the documents of
  a mixed index. A graph created by `sync --graph` now covers the whole tree instead of
  only the changed files.
- **Safer config handling.** `EnsureConfig` no longer overwrites a config with invalid
  JSON and merges into a partial one (keeping a `.bak`); saving in the web UI or the
  TUI keeps keys it does not know and does not persist start-up fallbacks such as the
  embedded llama-server URL.
- **Graph fixes.** A call stub no longer shadows the real declaration, paths and
  symbols with commas or quotes update incrementally, and a failed file read no longer
  leaves a half-deleted graph.
- **Smaller fixes.** Boolean search flags (`--json`, `--rerank`, ...) no longer swallow
  the next word of the query; `gleann serve` exits 0 on SIGTERM and stops the embedded
  llama-server; a query with the wrong dimension returns an error instead of a panic;
  proxy hosts, webhook secrets, conversation IDs and update `sources` are validated or
  redacted; `PATCH /api/indexes/{name}` reports `graph_stale` when it cannot update an
  existing graph.
- **Documentation** now matches the code for the plugin protocol (`/health`, `/info`,
  `/convert`), `plugins.json`, MCP tool names, environment variables and the REST routes.

## Packaging

The Linux full build no longer bundles `libmvec` (it comes from glibc) and its RUNPATH
is `$ORIGIN:$ORIGIN/../lib`. The glibc 2.39 floor of the full build is unchanged; ARM64
full builds are not yet verified on older distributions.

## Upgrading

- Open the web UI through the link `gleann serve` prints, or run `gleann token show`.
- Point OpenAI-compatible clients at `GLEANN_API_TOKEN` or a token from `gleann token create`.
- A `server_addr` of `:8081` in `config.json` stays as it is; change it to `127.0.0.1:8081`
  unless you want the server reachable from the network.
- To make an existing recompute index fast: `gleann index storage <name> --set store`.
