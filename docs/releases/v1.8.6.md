# gleann v1.8.6

This release fixes a bug that could silently damage vector indexes, and a broken
`gleann install`. **If you used `gleann index sync`, the file watcher or the
update API before this release, check your indexes after upgrading** (see
"Upgrading").

## Highlights

### Index corruption fix

Updating an index in place used to corrupt it. When a file was changed, deleted
or renamed, `gleann index sync`, the watcher, `POST /api/indexes/{name}/update`,
`Reconcile` and memory-entity deletion removed that file's passages and vectors
in place. Passage IDs came from an ever-increasing counter, so the removal left
permanent gaps, while the vector backends address a vector by its position. Later
vectors then pointed at the wrong passages: searches returned the wrong text, or
far fewer results than a freshly built index, and no error was reported.

What changed:

- Appending new passages is still done in place and only embeds the new texts.
- Anything that removes passages now **rebuilds the index from the remaining
  passages** (a "compaction"), which renumbers them densely. Embeddings are
  computed before any file is touched, so a failure leaves the index as it was.
- An index that already has gaps from an older version is repaired the next time
  it is updated.
- Removing the last passage empties the index; a later add builds it afresh.

### `gleann index repair` and a new `doctor` check

- `gleann doctor` now lists damaged indexes and tells you which command fixes
  them, and summarises every index on one line (passages, backend, model,
  dimensions, size on disk).
- **Searching a damaged index warns**: a log line, a `warnings` field in the
  search API response, and a line above the results in the MCP search tool, so
  nobody trusts wrong results unknowingly.
- `gleann index repair <name>` (or `--all`) rebuilds an index's vector index
  from the passages it already stores. The source files are not needed, and
  embeddings come from the embedding cache where the texts are unchanged, so it
  is usually fast. It shows progress while re-embedding (`--progress
  plain|json|none`). `--check` only reports (exit status 1 if anything needs
  repair); `--force` rebuilds even when the check finds nothing.

### `gleann install` works again

`gleann install --user/--system` copied the extracted `gleann-full-bin` instead
of the self-contained launcher, which then failed with `error while loading
shared libraries: libgleann_core_rs.so`. It now installs the launcher. It also no
longer falls back to `sudo` when the target directory does not exist yet (a fresh
home without `~/.local`). `gleann help` lists `install` and `uninstall`.

## Also in this release

- **Update statistics**: an update reports how it was applied (`in-place`,
  `compact`, `emptied`, `noop`) and what it cost (passages added/removed, texts
  embedded, timings). `gleann index sync` prints it, `POST
  /api/indexes/{name}/update` returns it, and `/metrics` counts it
  (`gleann_update_requests_total{mode}`, `gleann_update_latency_avg_ms`,
  `gleann_update_embedded_texts_total`).
- **Optional Ollama API key** (`ollama_api_key` / `OLLAMA_API_KEY`) for Ollama
  behind an auth proxy or hosted Ollama; an OpenAI key is no longer sent to
  Ollama endpoints, and `gleann config show` masks API keys.
- **`gleann index sync`** now uses the backend the index was built with (it used
  to fail with `backend "" not registered`, or rewrite the index with another
  backend), and a full rebuild keeps an index's tags, description, MCP exposure
  and creation time.
- Embedding progress is now actually reported during index builds (the progress
  hook never matched the embedders' method signature before).
- `DELETE /api/indexes/{name}` no longer fails on Windows while searches still
  hold the index open.
- A new in-process index build/sync pipeline (`internal/indexing`) shared by the
  CLI, the server and the TUI; config files are written with mode `0600`.
- Server hardening: path traversal, secret redaction, SSRF, searcher reference
  counting and leaks.
- `RemoveVectors` was removed from the vector backend interfaces (see the
  changelog); out-of-tree backends can drop it.

## Upgrading

1. Install the new version. With the self-extracting launcher, run
   `gleann install --user` from the downloaded file.
2. Check your indexes: `gleann doctor` (or `gleann index repair --all --check`).
3. Repair what it reports: `gleann index repair --all`. If you suspect an index
   that the check calls healthy, `gleann index repair <name> --force` rebuilds it
   regardless.
4. An index whose passage store is missing or unreadable cannot be repaired from
   itself; rebuild it with `gleann index rebuild <name> --docs <dir>`.
