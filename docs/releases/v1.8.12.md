# gleann v1.8.12

Multilingual retrieval gets better out of the box: the model catalog now ships a
correctly converted multilingual-e5-small. Reranking runs in-process with bitllm.c,
so the `eif` build no longer needs an external server to rerank. The embedded
llama-server is updated to llama.cpp b12176 and now also ships for Linux ARM64.

## Upgrade notes

- **Rebuild indexes made with `multilingual-e5-small` from the catalog.** The previous
  GGUF was converted with the wrong tokenizer (`llama` instead of the original
  Unigram/`t5`), so non-English text was split into the wrong pieces. The new file gives
  different embeddings and does not match old indexes. Run `gleann models download
  multilingual-e5-small` (the old file has a different size, so it is replaced), then
  `gleann index rebuild <name>`. On MTEB XQuADRetrieval (Turkish)
  nDCG@10 rises from 0.905 to 0.936; on TurHistQuadRetrieval from 0.392 to 0.409.
- **Loopback clients are no longer rate-limited.** Requests that connect directly from
  `127.0.0.1` or `::1` (the CLI, the MCP server, local scripts) skip the limiter. Requests
  forwarded by a local reverse proxy are still limited by the forwarded client address.

## Highlights

- **In-process cross-encoder reranking (`reranker: eif`).** With the `eif` build, the
  reranker scores (query, passage) pairs with a GGUF cross-encoder through bitllm.c, using a
  pool of single-threaded workers. Before this release the reranker was silently skipped
  when the embedding provider was `eif`. Tested models: `mmarco-mMiniLMv2-L12-H384-v1`
  (multilingual, about 0.4 s per query for 20 candidates on an ARM CPU) and
  `bge-reranker-v2-m3`. A GGUF that is not a cross-encoder is rejected, and a model name
  resolves under `~/.gleann/models` (preferring `q8_0`) with no fallback to another model.
- **`rerank_pool` in REST search** sets how many candidates go to the reranker
  (default `max(4*top_k, 50)`).
- **llama.cpp b12176** (was b4898) for the embedded llama-server, for `linux-amd64` and,
  new, `linux-arm64`. Other platforms build without an embedded server. On first start
  the new files are extracted to `~/.gleann/bin` and the old b4898 libraries are removed.
  The runner waits until `/health` reports the model loaded and fails fast if the process
  exits; `--mlock` is no longer passed; server logs go to stderr, so `--json` output stays
  valid.
- **bitllm.c** loads single-linear and F16 classifier heads, and refuses GGUFs whose
  embedding or attention weights are neither F32 nor Q8_0 instead of returning wrong
  vectors.

## Benchmarks

On an ARM CPU (NVIDIA GB10, 20 cores, CPU only), the in-process bitllm.c path is faster
than llama.cpp b12176 on the same inputs: 1.9x to 9x for embedding and 1.6x to 2.8x for
reranking. With more threads than performance cores, llama.cpp slows down on this CPU;
use `-t 10` there.

## Packaging

- The embedded llama-server needs `libgomp.so.1` and `libssl.so.3`. The full Docker
  image now installs `libgomp1` and `libssl3`.
- The ARM64 llama-server needs glibc 2.38 or newer (amd64: 2.34). On older systems, such
  as the Debian bookworm based Docker image on ARM64, use the in-process `eif` provider,
  which does not depend on llama-server.
- The repository now carries the llama-server binaries for both architectures, about 61 MB.
