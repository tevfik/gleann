# gleann v1.20.1

A fix release. It stops data from going to OpenAI's cloud, or to the wrong
server, when the `openai` provider has no endpoint configured. It also
raises DiskANN's search recall, improves keyword search in small and
Turkish indexes, and fixes the code graph's split and phantom symbols (#12).
The index format is unchanged and nothing has to be rebuilt; Turkish indexes
refresh their keyword table by themselves on the first search.

**Read "Upgrading" if you use OpenAI's cloud:** gleann no longer reaches it
unless you set its URL.

## Security

gleann now sends data to api.openai.com only when that URL is configured
(`openai_base_url`, `--openai-base-url` or `OPENAI_BASE_URL`). Without an
endpoint, chat, embeddings, summaries and model listing fail with
`openai endpoint not set` before anything is sent. Each provider now gets
only its own endpoint and key.

Before this release:

- **Embeddings went to OpenAI's cloud.** An OpenAI-compatible URL on port
  11434 (Ollama's own `/v1` API) was rewritten to `https://api.openai.com`,
  and an empty `openai_base_url` defaulted to it, so a whole corpus could
  be embedded in the cloud.
- **Chat went to the Ollama host with the OpenAI key.** `gleann chat`, the
  TUI chat and HyDE query expansion used `ollama_host` as the OpenAI
  endpoint.
- **REST:** `POST /api/indexes/{name}/ask` with `"llm_provider": "openai"`
  kept the Ollama host and sent `OPENAI_API_KEY` from the environment to it.
- **Proxy and A2A:** an OpenAI key left in the configuration was enough to
  switch them to the `openai` provider.
- **Other providers got the OpenAI key:** Anthropic, Gemini, and `memory`
  summaries.

One resolver now serves the CLI, TUI, REST, MCP, A2A and the proxy.
`openai_base_url` may end in `/v1`; it used to be doubled to `/v1/v1/...`.
`gleann doctor` reports a missing endpoint and marks OpenAI's cloud
("documents and questions leave this machine").

## Upgrading

If you use OpenAI's cloud and never set `openai_base_url`, set it once:

```bash
gleann config set openai_base_url https://api.openai.com/v1
```

Otherwise `openai` chat and embeddings stop with `openai endpoint not set`.
Setups with Ollama, Anthropic, bitllm.c, or an OpenAI-compatible server
(vLLM, llama.cpp, LM Studio) whose URL is in `openai_base_url` work as
before.

## Fixed

- **Keyword search in small indexes.** The keyword leg drops query words
  found in more than 20% of an index's passages. In an index of one
  document, those are the document's subject, which questions name ("In
  NIST SP 800-53 Rev. 5, what is the name of control AC-11?" was searched
  as `what name`). The cut now applies only from 10,000 passages, where it
  keeps queries fast. On 18 PDFs indexed one per index, the answer reached
  the LLM for 31 to 33 of 34 questions instead of 30.
- **Turkish suffixes after an apostrophe.** "İş Kanunu'na göre" was
  searched as `kanunu`, `na`, `göre`, and `na` matched unrelated passages.
  Turkish indexes now drop the suffix after an apostrophe ("Kanunu'na",
  "AB'ye", "2023'te"); a capital after it ("O'Brien") is kept. Each Turkish
  index rebuilds its keyword table once, from its stored text, on the first
  search after the upgrade. Nothing is re-embedded; other languages are not
  touched.
- **`"hybrid_alpha": 0` in the REST search API** (`POST
  /api/indexes/{name}/search`, `POST /api/search`) was ignored; it now
  searches by keywords only. A value outside `[0, 1]` answers 400.
- **The proxy no longer drops indexes silently.** With several indexes, one
  it cannot search (old store format, missing, failing to load) is still
  left out, but logged and listed in the pass-through reply's
  `X-Gleann-Skipped-Indexes` header.
- **DiskANN recall.** The searcher reranked only the first 2×top-k
  candidates (by PQ distance) with exact distances and ignored
  `search_pq_rerank`. PQ misorders close neighbours, so recall@10 stayed
  flat whatever `search_l` was. It now reranks all `search_l` candidates
  by default, and `search_pq_rerank` sets the width. Recall@10 on
  synthetic data (bench/vectordb):

  | | before | after |
  |---|---:|---:|
  | 10K × 384, `search_l` 100 | 0.919 | 0.998 |
  | 100K × 768, `search_l` 64 | 0.651 | 0.880 |
  | 100K × 768, `search_l` 128 | 0.669 | 0.968 |
  | 100K × 768, `search_l` 256 | 0.672 | 0.990 |

  Latency at the same `search_l` is unchanged. On large indexes, set
  `search_l` to 128–256 for recall@10 of 0.97–0.99.
  On indexes built with pruned embeddings, a wider rerank re-embeds more
  passages per query; lower `search_pq_rerank` if that is too slow.
- **Code graph: split and phantom symbols (#12).** A function the chunker
  cut into several search passages became several graph symbols
  (`Name_part2`, ...); it is now one symbol per declaration, and its calls
  and callers attach to it. Names inside the indexed module that are not
  declared symbols (builtins, conversions, locals) are no longer stored as
  external call targets. On gleann's own repository: 0 split symbols (was
  3,570), 0 phantom nodes (was 1,074), and about 3,200 real call edges
  gained. A sync updates the graph of the files it touches; run
  `gleann index rebuild <name>` to redo the whole graph (it also
  re-embeds the index).
- **`gleann index migrate`** refused a correctly copied index when a
  sampled passage had ten or more near-copies that outrank it on its own
  words (a PDF's chart tick labels): `passage N is not its own top-10
  lexical hit`. Such a passage now passes when its row holds its text and
  its lexical row contains all of its words. If v1.20.0 refused one of
  your indexes this way, run `gleann index migrate <name>` again.
- **A2A:** the task state machine refused to resume a task waiting for
  input (`INPUT_REQUIRED`). No skill asks for input yet; multi-turn A2A is
  planned for v1.21.
- **Upload on Windows:** a file name that reduces to nothing (`..`, `/`,
  `\`) gave 500 instead of 400.

## Added

- **`bench/vectordb`**, a benchmark for vector databases (RFC 006, step 1):
  load, cold start, recall and latency over a search-width sweep, filtered
  search, a one-file update and footprint, on synthetic data with exact
  ground truth. It measures gleann's own `hnsw` and `diskann` backends so
  far; candidate databases follow. It is a separate Go module and does not
  change gleann's dependencies. Run it with `make bench-vectordb`.
